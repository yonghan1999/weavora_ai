# 同步广播与会话生命周期调度隔离

## 真实缺陷

`a87f426` 已包含单次阻塞写入两秒期限，以及撤销投递入口先关闭目标账号的修复。但 SyncOutboxDispatcher、空闲同步会话复核、租约清理和失效账号清理仍共用一个单线程调度器。多条未读取连接令一次广播连续等待多个写入预算时，无关账号已经完成 logout 的空闲连接仍不能及时进入复核。

新增真实回归启用生产定时调度、临时 PostgreSQL 和 Spring/Tomcat：一个账号建立四条实际 TCP/WebSocket 连接并在合法 101 握手后停止读取，另一账号建立正常读取的空闲 WebSocket。通过 OutboxService 逐条持久化只向慢账号授权的约 32 KiB 合成传输探针，不手工调用广播或复核。测试采样实际线程栈，确认生产 SyncOutboxDispatcher 仍在 Tomcat `sendMessageBlock` 中，并查数据库确认该事件尚未完成同步，再执行另一账号真实 logout，从事务返回开始要求其空闲连接五秒内收到 1008 关闭。

旧实现实际在五秒等待超时。合成大载荷只是触发真实 TCP 背压，不作为产品消息容量模型或全部通道五秒验收。

## 修复

为 SyncOutboxDispatcher 分配独立单线程 `syncDeliveryScheduler`，固定延迟仍为一秒，Outbox 顺序、事务及同步完成确认不变。默认单线程调度器继续负责原生命周期维护，已有外部撤销三线程调度器不变。只增加一个固定调度线程，不创建每连接线程、异步发送队列或重试框架。

同时收紧会话复核的锁范围：当前仍有效的会话只查权威状态，不为无状态修改等待发送锁；失效候选仍取得原连接锁，再次检查状态后调用原有注销与关闭路径。这不是跳过失效校验、使用缓存或无锁关闭：广播/回放仍自行校验，真实关闭仍与该连接在途写入串行。由此避免有效慢连接把默认生命周期线程重新拖到发送锁上。
