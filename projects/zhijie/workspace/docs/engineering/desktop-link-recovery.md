# 桌面后台循环的断链与离线资格清理

## 验证范围

在 `114b139` 已有真实会话/同步后台循环联调上增加三种网络中断用例，不改产品实现、时钟、凭据 TTL 或数据库到期字段。Java 测试专用 TcpTestLink 只在随机 127.0.0.1 端口转发真实 TCP 字节；断链时关闭既有套接字并拒绝新连接，恢复后仍使用同一个客户端和后台任务。不解码或记录请求头、正文及凭据，不修改系统路由、防火墙或试用数据。

Rust 继续实际并发运行生产 `session_loop` 与 `sync::maintain_connection`，夹具只等待状态与通知，不调用 tick、refresh、recover 或 connect_sync。三条路径均要求断线后生产重连确实被拒、服务状态变为 Retrying，恢复后收到离线期间持久化消息的同步通知，再用当前凭据实际 HTTP 读到该消息。服务恢复须显示 Connected，恢复时间从放行链路计算，要求不超过十五秒。

- 短失联：观察实际离线状态后再保持六秒，恢复后本地与数据库的原活动、租约及 IP 不变，不产生凭据旋转。
- 离线撤销：链路不可达期间从真实服务端执行当前设备离房；恢复后原活动清空，但账号及群读取仍有效。数据库要求旧租约撤销、活动指针删除、地址释放。
- 长失联：不调整期限，等待生产心跳维护自行清空本地活动，再等生产服务端 ACTIVE→GRACE→释放过程结束，确认活动指针和地址已释放。放行后可继续读群消息，但不得自动复活原活动或新增租约。

该范围是服务控制连接中断，不是对语音或 TUN 数据链路注入弱网。离线撤销以同设备远端 leave 触发，不冒称踢出、退群、结束活动等全部撤销入口均完成。
