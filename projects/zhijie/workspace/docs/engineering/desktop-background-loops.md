# 桌面会话与同步后台循环联合验证

## 覆盖范围

`5122dd3` 已验证真实十五分钟续期、生产服务端调度及逐轮消息，但客户端维护、旧连接关闭读取与重连由测试夹具驱动。本次新增无窗口 Rust 父夹具，实际并发运行桌面使用的 `session_loop` 和 `sync::maintain_connection`，不在夹具中调用 tick、refresh、recover、connect_sync 或手工重建连接。产品行为没有变更，仅在 cfg(test) 下登记新入口。

Java 创建临时 PostgreSQL、启用生产调度的 Spring/Tomcat、随机临时账号和活动，等待两个真实后台循环就绪。每轮用生产 MessageService 写入一条普通消息，Rust 必须先收到生产同步循环发出的群消息通知，再以当前凭据通过真实 HTTP 读到指定消息。Java 同时检查服务端恰有一条同步连接、原租约有效、成员 ACTIVE、原 IP 保留；Rust 核对本地活动、原租约和地址。

快速用例只将客户端本地 access_expires_at 提前，等待生产十五秒维护循环真实旋转凭据；不改服务端 TTL。显式长测保留原十五分钟有效期，自动等待实际刷新与原凭据过期后至少十五秒，要求至少六十轮消息，以及凭据旋转后的实际消息通知。两种用例最终均禁用临时账号，等待生产同步恢复/会话维护自行清空本地会话和活动，不由夹具主动执行清理逻辑。
