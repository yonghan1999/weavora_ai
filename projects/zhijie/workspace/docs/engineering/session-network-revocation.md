# 登录失效后的真实网络数据面隔离

## 范围与实现

基于 `8471c58` 的具体登录绑定修复及 `a90903b` 试用包，本轮只增加测试和工程记录，不改变生产协议、依赖、数据库迁移或制品。控制面拒绝旧票据不再作为已建立网络通道停流的替代证据。

`NetworkProbeRevocation` 统一真实 HTTP 登录、普通刷新、注销及刷新重放，密码仅在内存生成和传递；活动加入和签票使用真实鉴权 `AuthSession`。会话到期场景只将独立临时数据库中目标会话的 `expires_at` 置为过去，不直接修改活动、租约、grant 或 Outbox，也不伪称等待三十天自然到期。

先加入并签发票据，再正常刷新，确认同一登录会话的旧活动票据仍有效；数据面建立后才执行注销、旧刷新令牌重放或会话到期。撤销前要求票据至少还有十秒有效期，隔离后再次确认未自然过期。新的认证场景始终开启生产调度，不手动调用清退或投递；五秒内同时检查租约撤销、活动指针删除、grant 清退及唯一 `network.revoked` 事件。

## 数据面断言

- Direct 六场景：三种登录失效 × 接收端权威在线/黑洞。实际双向 WireGuard 加密流量建立后，旧端持续发送至少三十个数据包，再真正发送新握手，均不能投递至接收端 `TunnelDevice`。在线接收泵继续运行；黑洞接收泵按生产三秒权威期限失败关闭并释放设备，不依赖恶意端 Stop。
- Relay 六场景：三种登录失效 × 权威在线/仅目标票据 HTTP 黑洞；关闭管理推送以独立检查权威轮询和期限。真实三端 QUIC 四个方向先通流，失权源和目的两个方向停流，其他两方向继续，旧发送任务仍尝试至少一百次；恢复权威后旧票重连真正获得拒绝。
- Relay 自动推送三场景：目标权威请求已挂起，再撤销认证；生产每秒扫描、同步 Outbox、外部投递及真实管理 HTTP 自动完成，不手动 dispatch。测试包装真实 `ControlPlaneValidator` 仅记录最后一次成功请求的起点，并记录 QUIC 接收任务实际关闭时刻。独立调度和三秒权威期限存在竞态：关闭比期限早至少一百毫秒才记为 `path=push`，否则明确记为 `path=deadline_or_push`，不冒充推送先于超时。两种情况都必须五秒内隔离且目标管理事件实际 delivered；既有手动即时投递回归仍严格要求早于权威期限。包装不替换或放宽真实验证结果。

既有离房恶意端和 Relay 黑洞/推送回归仍保留。认证令牌、网络票据、测试私钥和管理密钥不得出现在探针日志。Direct 的 `observed_ms` 记录隔离信号而非后续 Cargo 进程退出，避免把清理延迟当成业务停流耗时。
