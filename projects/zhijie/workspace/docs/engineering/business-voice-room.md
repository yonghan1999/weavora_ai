# 真实业务满房：十二个独立语音进程

本机非组合模式实际通过。PostgreSQL、Spring 活动成员与租约、nginx 鉴权代理和 LiveKit SFU 均参与。十二个独立 SDK 进程使用各自的控制面票据连接，同一房间内实际发送并解码受控音调。不是使用诊断工具自行签发的票据，也不是十二台设备。

## 实测结果

- `VoiceSignalingIntegrationTest` 一项执行、零失败、零跳过，153.6 秒。满房媒体观察 75 秒，132 个有向发送/接收组合各有五个 15 秒窗口，合计 660 个。非静音帧范围 1,490～1,510；每个窗口均经 Rust 原断言检验：至少 1,200 帧，解码音调与指定发送端的频差小于 15Hz。
- 控制面完成五批十二端心跳与重新签票。第十三名加入被 `CAPACITY_FULL` 拒绝，原十二张票据过期后经代理验证均为 HTTP 403。所有客户端、专用 SFU、代理和临时数据库退出；7880/TCP、7882/UDP 已释放。
- 同一次 Java 执行还经过原有双端媒体控制、解散及禁用账号场景。日志中有外部撤销待投递警告，不据此认定所有外部撤销任务都成功。此轮未运行网络 Helper，也未改变正在试用的后端或应用。

## 入口及证据

在原 `VoiceSignalingIntegrationTest` 媒体环境上设置 `ZHIJIE_TEST_ISOLATED_VOICE=true`，并保持 `ZHIJIE_TEST_COMBINED_CHANNELS=false`。默认未设置时仍用原单进程模式。协调器仅将各自票据、业务身份映射和必要媒体参数传给客户端；每个客户端用实际 SDK 身份对照控制面提供的用户和成员代次。在共同窗口收完另外十一名成员的音频后才允许离开。汇总拒绝错身份、重复/缺失方向、错音调标识、不同开始时间或不完整窗口。

本地原始证据位于 `target/voice-entry-3899812074467051207/`，含十二份客户端日志及 `rust-full-room-media.log`（SHA-256 `59ec26e1e69e088517e3e121137bb0e41f5f9539f0d9cdc2639571e00f4c31e3`）。`target/business-room-675997f/ordinary.log`（SHA-256 `bbc856f63b19f34dca194c5bd8b9e863cab92837b35a71536f4db541814ac49d`）为本轮 Maven 输出；以本次实际运行的测试为准，不以同目录历史报告计数。日志与构建缓存留在 D 盘。

## 未验证范围

这是同机合成音业务链路，不证明人工听感、真实音频设备、跨机质量或一小时稳定性。没有重跑原先已达重试上限的组合；七窗并行游戏网络及网络权限撤销后语音独立继续，仍需获准后实测。此前间歇性卡顿未关闭，正式任务状态未改变。
