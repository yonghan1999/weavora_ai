# Relay 内存授权快照与有界续验

## 需求与复现

补齐原架构撤销与隔离第 3 项：Relay 每个数据报使用内存中的当前租约、活动/成员代次、策略和目标映射，不再对每个来源/目标数据报执行远程 HTTP 验权。权威资格仍由控制面判断，快照不能无限延长失权端点通信。

`authorization-cache-before.log` 在真实 QUIC 下复现：两端已认证后，闩锁阻塞后续验权；发送方的数据报在 500 毫秒内不能交付，一项失败。夹具确认验权已经进入且未释放，不通过改短远端延迟掩盖阻塞。

## 实现与安全边界

- 控制面验证响应补齐 `version=1`、活动代次、设备标识和票据/租约较早的绝对过期毫秒数，保留原成员代次、租约、用户、策略、来源 IP 与路径限制。未通过当前账号、群、活动、成员、租约、指针、地址或策略检查仍拒绝。
- 认证成功将不可变会话身份和单调时钟截止存入现有会话表。截止最多为该次请求开始后三秒，并且不超过返回的绝对票据/租约期限；等待远端和线程容量的时间不能重新计为新授权寿命。
- 每个会话每秒异步续验，与数据报读取及独立截止计时并行。同会话最多一个续验，全 Relay 最多 32 个实际阻塞验权；连接任务仍最多 128 个。等待容量受现有握手或授权截止约束，不按数据包创建任务。HTTP 继续一秒连接、两秒完整请求期限。
- 每个数据报在最终转发锁内检查来源和目标：当前连接映射、身份、两端未过期、同活动/活动代次/策略且未命中 deny。目标必须来自已验证的同活动 IP 映射，不能自选跨房来源或目标。旧低代次握手不能覆盖更高代次映射。
- 成功续验只允许相同票据、活动/成员代次、租约、设备、用户、来源 IP 和策略，允许实际期限更新；身份变化、失败、过期或迟到均关闭。原截止与响应同时就绪时截止优先；过期会话或已撤销/替换映射不能被迟到成功续验复活。
- 现有主动撤销仍和注册、最终转发共用状态锁，立即拒绝来源和目标，并关闭对应代次会话。权威响应严格要求 HTTP 200、最多 4,096 字节、必要快照字段；固定错误不回显响应或凭据。

健康权威下每秒复核，慢权威/断连最多使用请求开始后三秒且不超过原票据/租约到期的授权。未收到主动通知时存在短暂缓存窗口，不再承诺权威事务提交后第一个数据报即拒绝；该零窗口也不是原五秒验收要求。主动撤销、周期续验、到期硬截止组合，不以客户端自愿停止替代服务端措施。

复用既有会话表、撤销锁、验权接口与 bounded 连接任务，不增加依赖、独立缓存系统或数据库表；数据面与权威 I/O 分离，并复用统一身份/截止检查，遵循单一职责、DRY、KISS、YAGNI。

## 兼容与运行

响应新增必需字段；新 Relay 拒绝旧控制面缺失字段，不使用无限期或宽松默认值。旧 Relay 对新增字段可忽略，但这不代表混版已经验收。实际升级停止相关进程，使用匹配控制面/Relay，并保留成套旧程序、配置及停库备份；未修改现有试用库。没有新迁移，仍为 V16；没有安装驱动、启动原生桌面或改防火墙。

墙上时钟用于把权威绝对期限转换为本机单调截止；转换后不因本机时钟倒退延长本次快照。跨机时钟偏差、Internet 迟延、目标服务器容量、系统 TUN 与实际游戏仍须实机验证，不能据同机测试宣称完整五秒 SLA 或离线可用。既有 `a039409` 试用包不包含本轮快照变更。
