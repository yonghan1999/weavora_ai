# 外部撤销调度隔离与持久化退避

后续已进一步拆分语音、网络及其他外部分区的实际定时器与事务，见 [外部撤销通道并行](external-revocation-channels.md)。本文保留当时单外部任务的实现与证据边界，不将后续能力追溯到旧试用包。

## 需求与失败依据

本轮继续实现原架构撤销与隔离第 2、5 项以及 AC-026/032/035 的相关开发要求，不变更五秒撤销目标或原批准范围。V15 已将同步完成状态与外部成功拆开，但原派发方法仍在同一定时线程及事务中先同步、后阻塞式投递外部目标。一百条外部永久失败也仍占住外部队列，妨碍后续可投递事件。

`ExternalRevocationIsolationIntegrationTest` 在真实 Spring/PostgreSQL/WebSocket 下保留两项失败，见 `target/external-revocation-isolation-9c6275a/before.log`：

- 实际定时器进入受控慢目标后，新提交消息在三秒内收不到，等待超时。测试使用闩锁确认慢目标已开始且未释放，不通过降低产品超时或把通知改成手动派发规避。
- 一百一十条有效 `network.revoked` 先入队，再加入一个正常外部目标事件；连续三轮派发仍未完成该正常事件。

## 实现边界

同步和外部投递拆为独立 Spring 服务，每个保留一条定时任务和独立事务。默认 `taskScheduler` 维持单线程，继续串行同步、租约/禁用账号/在线状态及同步会话复核；新增单线程 `externalRevocationScheduler` 仅运行外部撤销，不将整个默认调度池扩大后让业务任务无约束并发。`RevocationDispatcher` 只保留既有手动组合入口，先调用两个受代理的服务，不持有外层事务；生产自动调度各自执行。

V16 在原 Outbox 增加 `external_attempts` 和 `external_next_attempt_at`。外部失败保留 `delivered_at=NULL`、原同步完成时间和事件游标，同时累计原总尝试次数；独立外部计数只负责计算 2/4/8/16/32/60 秒、之后最大 60 秒的退避。该计数不从旧总尝试次数推断，避免把历史同步失败误当外部尝试。退避时间落库，重启不会立即把整个失败积压全部重试。

只选择同步已完成、整体未完成且已到重试时间的事件；按 `COALESCE(external_next_attempt_at, occurred_at)` 及同步序号排序。旧失败退到未来，后续事件可尝试；到期重试也不会被不断进入的新事件永久排后。仍使用一百条有界批次，不新增队列系统或依赖。单个外部目标失败不终止批内其他事件，不恢复任何资格。

每轮失败只输出固定告警及失败计数，不附带事件、用户、群、目标 URL、原始异常、载荷或凭据；原指标增加固定 `external/failed`、`sync/failed` 标签，整体完成与观测计数共用 `OutboxDeliveryStatus`。职责分离和复用遵循单一职责与 DRY；一条新增工作线程、两个列及既有事务/Mapper 保持 KISS/YAGNI。

## 迁移与运行限制

仅迁移本轮独立临时数据库，没有修改已有试用环境或生产数据。实际升级应停止旧控制面和写入进程，核验升级前停库备份，用迁移角色运行 V16 及现有 `grant-runtime.sql`，再启动匹配的新程序。已有运行角色对 Outbox 的更新权限覆盖新列，不增加角色/表权限，不放宽管理记录或迁移历史保护。不得混跑或直接降级程序，沿用 V14/V15 的游标与备份回退边界。

外部调用仍受具体适配器现有超时约束，同一外部批内仍为顺序调用；没有证明 SFU 与 Relay 之间完整并行、跨进程派发独占、严格一次副作用、外部长积压五秒完成或实际媒体/TUN 失权。数据库/默认同步任务自身慢仍可能拖延默认调度，不能称为通用故障隔离。未配置外部目标仍失败并告警，不能据此声称邮件/Relay/语音接入完成。后续可选 Relay 主动撤销的实现、配置和实际组合检查见 [Relay Outbox 主动撤销](relay-outbox-revocation.md)，不追溯为本轮旧包已包含该能力。原生桌面启动、人工试音、管理员 TUN、跨设备及三平台环境不在本轮执行。
