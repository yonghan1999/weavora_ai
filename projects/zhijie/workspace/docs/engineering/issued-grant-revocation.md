# 已签发票据的权威撤销与认证注销边界

## 真实验证范围

`IssuedGrantRevocationIntegrationTest` 创建临时 PostgreSQL、生产 Spring HTTP 服务和真实调度器；账号、群、邀请、房间、加入、刷新、签票及可用的治理操作均通过实际 HTTP。语音使用生产签名器和信令鉴权入口，不建立媒体；外部语音管理目标是本测试独占的回环 HTTP 503 服务，Relay 管理投递未启用，撤销待投递告警及 Outbox 保留，不能误连本机已有媒体服务。

两个账号持有实际签发且尚未到期的网络票据与语音 token，并注册真实 Peer。每例先核对网络验证 200、Relay 权威验证 200、语音信令鉴权 204，以及另一端能查询到目标 Peer。再轮换目标账号访问/刷新令牌，确认普通认证续期不影响原活动票据。

覆盖离房、踢出、退群、移除成员、结束活动、删除房间、账号禁用、设备接管、切房与群解散十类。除禁用账号直接更新持久化状态外，动作都通过生产 HTTP 入口；禁用使用真实调度器检测，不代表管理端禁用 HTTP 已验收。服务端动作返回后，重放原网络票据、原 Relay 授权和原语音 token，必须拒绝；不调用客户端 Stop、离房补偿、手工 dispatcher 或本地清理来制造结果。

定向撤销要求另一账号原票据继续有效、Peer 列表不再包含失权方且心跳成功；全房撤销要求另一账号旧票据也被拒。接管与切房要求新租约及活动指针保留。五秒内确认旧租约和两类 grant 已撤销，两类外部撤销事件仍 pending；再等一秒重放旧票据，确保未复活。所有拒绝断言额外核对原票据尚未自然到期，不用 TTL 到期替代撤销。

## 认证注销不是完整活动退出

实际 HTTP 复现：单独调用 `/auth/logout` 后，原访问与刷新凭据被拒，但旧网络票据仍返回 200、Relay 权威验证仍返回 200、旧语音信令仍返回 204，另一端仍能查询到原 Peer，旧租约尚未撤销。这符合现有认证入口“只撤销当前登录会话”的实现，不应将其描述为已有活动/媒体/网络五秒撤销成功。另一个设备的认证会话单独注销也不会撤销当前活动。

独立对照通过实际 HTTP 先 `/activities/{id}/leave` 再 `/auth/logout`，旧网络、Relay 和语音信令资格均拒绝，同账号另一设备登录及不受影响成员保持有效。生产 Shell 该顺序的已有真实联调见 `logout-real-backend.md`；它不消除仅认证注销、离房请求失败、刷新重放撤销会话等路径的已签发资格边界。上一轮在线后台循环测试见 `desktop-online-revocations.md`，不能用合作客户端已清理覆盖该边界。

本轮不改变认证 API 语义、不新增会话到租约的绑定。若将所有认证失效纳入即时活动清退，必须同时处理同设备多登录、新活动接管、并发签票及锁顺序，不能简单按账号全撤销或让旧登录注销误伤新活动；该交付缺口保持开放。

KISS/YAGNI：使用现有 API、签名器及真实后台调度，不增加生产开关、协议或依赖。DRY：场景、签票、三种准入重放统一封装。单一职责：控制面夹具只验证权威判定与持久化撤销，不冒充媒体/系统网卡验收。所有新增临时、缓存及输出放 D 盘项目忽略目录，只设置当前进程环境；保留必要日志和交付物，完成后清理本轮不用的临时副本。
