# 活动绑定具体登录会话与失效撤销

## 缺陷与修复

此前 `a92851c` 的真实 HTTP 对照证明：单独调用认证注销会撤销登录，却不撤销已签发活动资格。修复前历史见 `issued-grant-revocation.md`。本轮不再依赖客户端先离房、主动 Stop 或本地补偿。

活动指针新增 `auth_session_id`，加入必须传入真实已鉴权 `AuthSession`，在群、账号及登录会话行锁内重新核验。恢复、心跳、离房和签票 HTTP 入口同样核对绑定；会话被注销、刷新重放撤销、密码重置撤销或会话生命周期到期后，旧网络票据、Relay 权威验证和语音信令资格均拒绝。普通访问令牌刷新与十五分钟 access 到期不改变已加入活动的归属，不以 access generation 绑定长期活动。

同账号、同设备再次登录不会自动继承活动。新登录显式加入创建新租约并递增成员代次，旧登录即使知道新租约也不能恢复、续约、签票或离开新活动；旧登录注销不会误撤新活动。已先完成鉴权但排队等待会话行锁的旧请求，在注销或轮换提交后重新核验，不能复活旧资格。

每秒调度扫描无效绑定，独立事务按账号、当前会话加锁并重读当前指针，再复用既有撤销服务清理成员、租约、grant、IP、活动指针及 Outbox。迟到候选不得清理新登录已接管的活动。不会按账号或设备猜测归属并批量撤销其他登录。

## V17 升级影响

`V17__activity_auth_session.sql` 添加可空外键和索引，兼容既有数据库结构。历史活动保持空绑定，即使有同账号同设备登录也不回填猜测；旧活动准入按拒绝处理，后台清退后用户须显式重新加入。新活动入口始终写入已核验的具体会话。迁移不删除账号、群或房间。

真实 PostgreSQL 升级测试从 V16 数据库写入历史活动后启动 V17，验证不猜测绑定、无效外键拒绝、旧活动拒绝及清理、显式重入、新租约不受迟到清理影响，以及会话过期后的扫描与清退。本轮不对生产库或现有本地试用数据执行迁移。
