# 十二端原生回调与接收队列诊断

## 结论及边界

2026-11-20（America/Los_Angeles），继续定位 `combined-channels.md` 中未通过的十二端组合检查。本轮没有重跑该组合，没有改变每方向每十五秒至少 1,200 个非静音帧、频差小于 15Hz 的验收要求，也没有将诊断退出零解释为质量通过。

新增计数已在一次 105 秒受控音调诊断中捕获完整 132 个远端方向同步下降：最后两个窗口原生回调分别只有 1,146～1,147、944～945 帧，观察窗口内远端 Rust 接收队列丢帧均为零。此次缺口已经存在于进入队列的原生 sink 回调，不是这些帧先进入队列又被队列溢出丢弃。这里只定位到该接收队列之前，不能进一步认定是发送、SFU、解码播放泵或宿主调度中的哪一层。

独立源码快照随后完成相同七窗口诊断，远端每窗口 1,499～1,501 个原生回调、非静音帧最低 1,499、观察窗口内无队列丢帧。两轮结果不一致，表明缺口具有间歇性。不能用较好的一轮覆盖较差的一轮，也不能据此声称普通通话不受影响。

## 实现范围

- 在既有本地 `libwebrtc` 补丁中增加非默认 `audio-stream-stats` feature，仅由 Voice 的开发依赖启用。复用已有溢出计数，额外在 Rust `AudioTrackObserver::on_data` 入口记录回调帧数及每通道采样数；不改 C++、定时器、调度优先级、默认十帧队列、丢旧保新策略或音频内容。
- 计数为单流累计原子计数，运行中各字段读取不是事务快照。诊断先读初值，观察后移除 sink，再读终值；接收队列中观察前已经存在的最多十帧可进入消费统计，因此总消费数不必等于本窗口原生回调数。初始溢出单独记录，不冒称启动阶段没有丢帧。
- `playout_cadence.rs` 复用原十二房间、十二发送源和 132 远端订阅，增加每十五秒窗口的原生计数、丢帧、消费与非静音计数。原生窗口边界在消费任务跨窗时采样，可能有调度偏差；不是每个原生回调的精确时间戳。全观察区间总计数更适合判断是否存在队列溢出。
- 支持一至七个窗口及静音/受控音调。音调限 `synthetic`，Rust 与 Python 均拒绝把音调送到系统输出。发送 48kHz 单声道、幅度 6,000、各端 300～1,400Hz 的受控 PCM，不读取麦克风，不产生可听输出。
- 运行器每约 500ms 通过 Windows API 记录宿主 busy 比例、客户端与 SFU 的进程 CPU 核占用，并保留测量开始时间。宿主比例包括其他进程，本工具不枚举、终止或修改它们。未采集内核调度追踪，CPU 相关性不能替代根因证明。
- 独立回环信令 17880、媒体 UDP 17882；随机短时凭据只经环境传给子进程，结束停止专用 SFU，并检查日志中没有临时 key、secret 或参与票据。所有缓存、临时文件和构建输出在 D 盘，未下载或安装工具，未改防火墙、路由或驱动。

## 实际观测

| 运行 | 范围 | 远端原生回调 | 队列溢出 | 结论 |
| --- | --- | --- | --- | --- |
| 首次静音，十五秒 | 132 远端方向 | 1,496～1,498 | 观察窗口均为零 | 短时不能解释历史失败 |
| 首次音调，十五秒 | 132 远端方向 | 1,499～1,501 | 观察窗口均为零 | 短时媒体可正常解码 |
| 音调，七窗口 | 132 远端方向 | 前五窗约 1,500；第六窗 1,146～1,147；第七窗 944～945 | 远端观察窗口均为零 | 已捕获进入队列前的回调不足 |
| 独立快照最终音调，七窗口 | 132 远端方向 | 各窗口 1,499～1,501 | 观察窗口均为零 | 未复现缺口，不等于修复或验收 |

较差七窗口：`target/playout-cadence-bfd68e99a0394d409c7a053a020ae136/`。远端第六窗非静音 1,102～1,112，第七窗 945～946；最大 Rust 消费间隔约 1,273ms。十二个本地源原生总回调 10,500～10,501，但源接收队列在观察中合计溢出 1,139 帧，表明源诊断消费者也曾延迟；这不等于发送编码丢了同样数量的帧。进程资源日志中有宿主 busy 达到 100% 的区间；该版本只有相对启动时间，没有最终版测量开始的绝对锚点，不把粗粒度资源区间严格配对为单个媒体窗口，也不归因为 CPU。

最终独立快照：`target/queue-cadence-338f5c0/snapshot-final-probe/`。远端总回调 10,499～10,500，最大消费间隔 41.472ms，整体音调频差最大 0.105Hz；本地源没有观察窗口内溢出。远端初始溢出最多 89 帧，发生于等待全部订阅就绪期间，未隐藏。最终七窗宿主 busy 平均约 51.35%～65.26%，单次采样峰值约 96.97%；客户端平均约 2.26～2.40 核，SFU 约 0.44～0.47 核。单机共享 SDK runtime，不等于十二台正式客户端；没有并行网络 Helper 负载、真实设备、弱网、跨机或一小时运行。
