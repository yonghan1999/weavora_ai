# 桌面生产后台循环的在线撤销验证

## 范围与观察方式

在已有真实会话与同步循环联合夹具中加入在线撤销参数化测试。每个案例创建独立临时 PostgreSQL 和生产 Spring HTTP/WebSocket 服务，启用真实调度；同时启动两个无窗口 Rust Shell 测试进程，各自实际运行生产 `session_loop` 和 `sync::maintain_connection`。父进程只创建场景、执行真实业务入口并观察，不调用客户端 tick、recover、刷新、断开或本地清理来制造成功，不修改时钟、凭据 TTL、心跳周期或到期字段。

撤销前两个账号在同活动分别持有真实资格、租约和 IP，均收到实际群消息通知并用当前凭据 HTTP 读到消息。服务端入口返回后计时，要求被撤销客户端五秒内清空本地活动；禁用账号及注销还必须清空本地会话和账号、显示 Disconnected。之后实际 HTTP 验证旧 heartbeat、resume、voice-grants、network-grants 均被拒；丢失群籍时群列表不能包含原群，原群消息读取被拒。再等一秒核对旧活动没有复活。

对定向撤销，另一真实后台客户端继续收到新消息，服务保持 Connected，原租约/IP 不变且实际心跳成功。结束活动、删除房间及解散群影响全房，因此另一端也必须清理，不将其当作不受影响对象。接管与切房额外核对新的服务端活动指针和租约未被旧端清理；接管代次递增、切房活动不同。
