# 同窗口音源与接收节拍

组合负载的三次失败不能由单独语音或单独联机通过抵消。本探针只提供对照：同一台 Windows 主机、一个隔离的 LiveKit 房间、十二名参与者、每端十一条远端流。十二个音源发布全零 48 kHz 单声道 PCM；对每条本地轨和每条远端轨，在同一个十五秒时间窗口统计消费的帧、样本、非零帧、样本绝对值峰值及最大消费间隔。不保存 PCM，不创建网卡。

在 `workspace` 设置本机离线 Rust 环境和 D 盘的 Cargo、临时目录后运行：

```powershell
python -B "scripts/local-preview/test-playout-cadence.py" --server "<已校验的本机 livekit-server.exe>" --media-address "<本机媒体网卡 IPv4>" --mode synthetic
```

信令仅绑定回环 17880，媒体使用所选本机地址的 UDP 17882；不改防火墙。默认 `synthetic` 不选择系统音频设备。`platform` 是另选的系统播放诊断，不是人工听感测试。汇总要求 12 个不同本地源和全部 132 个有向远端组合；不能用重复行补齐缺失方向。

本机观察记录 `target/playout-cadence-a1b98f8bbb954c09bbe84364131afb49/summary.json`、`synthetic.log`。每个本地源观察到 1500 帧、720000 个样本，峰值 0；每个远端方向 1500～1511 帧，所有方向中的最大样本绝对值为 2（16 位 PCM）。因此，远端虽有非零样本，却没有样本超过原组合测试的非静音阈值 100。最大消费间隔分别为 16.725 和 28.058 毫秒。开始观察前远端流已订阅，边界处可能消费少量已排队的帧；不要把帧数差额解释成传输增益或丢包率。

这轮只说明在**无 Helper 负载、合成设备、静音输入**的这次运行中未出现此前的明显帧数缺口。Rust 消费时间不是底层回调时间；结果不能区分组合负载下的发送、原生接收队列、播放调度或宿主资源原因。没有重跑失败的组合测试，也没有改变质量断言。下一步仍需在独立测试环境中取得带载同期数据。

## 满房失败时保留其他方向的观察

`livekit_media` 的满房探针现在等每个接收端的 11 个方向、以及全部 12 个接收端分别结束，再汇总质量断言。一个方向帧数或音调不合格仍会导致整体失败，但不会因此取消其他方向的测量。观察总截止、断线检查、非静音帧门槛和音调误差不变；断线或超时仍可能使记录不全。此前失败运行中缺少的记录无法补回。

离线回归：`cargo test --offline --locked -p zhijie-voice --test livekit_media -- observation_failure_preserves_other_receivers_and_directions`。该用例在 132 个任务中注入一次失败，核对其余 131 个执行完成、错误传到最外层，并确认缺少任务不能算作成功。它不连接 SFU，不证明真实负载或音质达标。
