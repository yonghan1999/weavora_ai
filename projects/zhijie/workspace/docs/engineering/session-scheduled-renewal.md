# 生产调度下的桌面凭据续期与同步联调

## 验证增量

此前真实十五分钟凭据续期已有通过记录，但父夹具关闭了服务端定时任务，长测也没有保持同步连接。本次仅增强 Java/Rust 测试，不修改产品实现、凭据有效期、数据库迁移、依赖或试用制品。

保留原有快速维护、排队同步恢复和注销用例；新增默认执行的生产调度快速用例，并将显式启用的十五分钟用例改为同时启用生产生命周期与 Outbox 调度。长测不修改时钟、客户端到期字段或数据库期限，每十五秒调用生产 `session::tick`，核对客户端活动、原租约及 IP，并在 PostgreSQL 检查租约有效、成员 ACTIVE 和原 IP 分配。

每轮通过生产 MessageService 持久化一条普通群消息，只把消息 ID 经匿名 stdin 发给 Rust；Rust 必须从真实 WebSocket 收到同一 ID 对应的 message.created。消息不手工广播或派发，必须由生产 Outbox 定时投递。父夹具要求每个维护轮次各有一条已接收消息，不能仅以 WebSocket 握手成功代替可用性。

真实刷新后，旧连接须在五秒读取期限内返回 ACCESS_TOKEN_INVALID；启用调度的用例不手工调用会话复核。随后调用生产同步恢复函数确认旧凭据不能覆盖新会话，以新凭据建立连接并继续收消息。最终要求会话代次为二、旧访问凭据 401、新凭据可读群、活动和原 IP 保留，再禁用临时账号并检查本地会话和活动清空。

## 边界与设计原则

这是本机临时 PostgreSQL、Spring/Tomcat 与无窗口 Rust 夹具的开发联调。服务端使用生产定时器，客户端使用测试十五秒循环调用生产维护函数；旧连接处理及重连由夹具驱动，不是 Tauri 窗口后台同步循环的完整验收。五秒断言从收到刷新信号后的读取等待开始，不作为全通道撤销 SLA 证明。

未覆盖真实音频、管理员 TUN、跨机游戏、多平台安装签名、目标服务器容量和长时混合负载；不推进正式 F/G/H/I，也不将 TASK-019～023 标为完成。本轮不重建制品，当前试用包仍采用已验证的 `684e0a9` 产品实现。

KISS/YAGNI：只增强既有夹具，不新增产品配置、依赖或调度框架。DRY：快测与长测复用同一维护、重连及消息核对路径。单一职责：Java 管理真实后端与权威数据库检查，Rust 执行客户端维护与网络结果断言。
