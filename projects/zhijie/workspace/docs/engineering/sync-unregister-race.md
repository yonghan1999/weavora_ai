# 同步连接注销后的悬空广播引用

## 已复现缺陷

`SyncService.unregister` 原先只从连接表删除会话，不更新该连接的 `closed` 标记。`ConcurrentHashMap` 迭代器可能已经取得后一个连接的引用：广播在第一个连接发送时阻塞，另一个线程注销后一个连接并返回，恢复广播后仍会向已注销连接发送。独立的并发测试使用两个实际登记的 `Connection` 和受控 WebSocket 发送，不依赖固定遍历顺序；原实现明确记录两个发送，而预期只有仍登记的一个。

另一个测试在发送阻塞时调用注销，原实现直接返回，不等待该连接的在途写入。注销完成后调用方不能以此作为该连接发送生命周期结束的边界。

## 修复边界

注销在原有原子 map 操作中取得被删除的精确 `Connection`，释放 map 操作后再获取该连接原有锁并设置 `closed`。广播和定时校验已在相同连接锁中检查该标记；注销返回后，持有旧引用的广播也不能再次进入发送。已经开始的写入先结束，注销不主动关闭传输，也不删除关闭期间登记的新连接。

等待连接锁发生在 map 操作之外，避免与发送失败路径中“连接锁 → map 操作”的顺序形成死锁。测试在注销等待在途发送时继续登记并注销同账号的新连接，验证新连接操作不会被旧连接等待阻塞。复用既有关闭标记、每连接锁和原子登记（KISS、DRY），不增加全局锁、重试、队列或依赖（YAGNI）；会话登记与传输关闭继续分离（单一职责）。鉴权、游标、回放上限、连接关闭原因和协议不变。
