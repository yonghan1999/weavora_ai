# Outbox 外部撤销积压与实时同步隔离

## 根因与失败复现

原派发器每轮仅取 `delivered_at IS NULL` 的最早一百条事件，依次发送同步通知和外部撤销；所有目标成功后才标记完成。未配置的语音/Relay 目标保持失败，超过一百条旧撤销事件会永久占满队首，使后续消息即使已经提交、仍无法实时推送。此外，外部重试会再次调用同步撤销的 `closeUser`，可能关闭用户后来重新建立的合法连接。

`SyncOutboxIsolationIntegrationTest` 使用独立 PostgreSQL、真实 Spring WebSocket 和手动派发：先写入一百一十条带有效 `user_id` 的 `network.revoked`，再连接到当前游标并提交群消息。原实现连续派发三轮后仍在等待消息时超时，记录在 `target/sync-outbox-isolation-a39d196/valid-payload-before.log`。早期 `before.log` 使用空 payload 对象，最终有效负载复现才是本缺陷的确认依据。

## 最小修复

- V15 在原 Outbox 增加持久化 `sync_delivered_at`，已完成历史事件沿用原 `delivered_at`，未完成事件仍保持待处理；不修改历史事件、游标映射或回放协议。
- 每轮先按已提交同步序号读取一百条未同步事件，调用独立的 `SyncRevocationTarget`，成功后记录同步完成；没有外部目标的事件同时完成整体投递。
- 外部队列仅读取已完成同步、但整体未完成的事件。外部失败继续累加尝试并保留待处理，不通过忽略异常或伪造成功消除积压。
- 同步目标失败时停止该轮同步，不跨过失败序号发送后续事件，避免客户端游标越过尚未发送的事件。
- 同步目标不再注册为外部重试目标，外部重试不会重复执行已完成的同步广播或关闭连接。

采用既有事件表、序号分配器和事务，不增加第三方队列、后台线程或依赖（KISS、YAGNI）；完成计数仍复用同一入口（DRY），同步与外部目标职责分离，不改变外部目标接口（单一职责）。`listPendingExternal` 显式表达新查询语义，避免把“全部未完成”与“等待外部投递”混用。

## 升级与回退边界

本轮测试仅操作自建临时数据库，没有迁移当前试用库或生产环境。实际升级须停旧控制面及写入进程、核验一致备份，以迁移角色运行 V15，再执行现有 `grant-runtime.sql` 并启动匹配的新控制面。沿用 V14 的禁止混跑和游标回退限制；不得删除迁移历史、重置同步游标或关闭校验。

新列属于运行角色原本可更新的 Outbox 表，不新增数据库权限、不放宽管理记录或迁移历史保护。旧完成时间保留；旧的外部失败事件不能据此推断此前同步是否成功，首次升级后可能再执行一次同步撤销。不要将升级描述为严格一次投递。崩溃发生在网络发送与数据库提交之间时，重启仍可能重复发送；已有游标去重不等于所有关闭连接副作用严格一次。

需回退时停止新程序，按已核验的升级前一致备份恢复匹配的程序和数据库；不要在迁移后的活跃库上直接启动旧程序。既有试用 ZIP 不包含本修复和 V15，不能称为已经更新的交付包。

## 仍未解决

本修复防止外部失败事件永久占据实时同步队首，不代表外部渠道已配置或撤销已完成。外部队列自身的最早一百条永久失败仍可能阻挡其后外部撤销；同步和外部投递仍共用调度及事务，慢外部服务仍可能延迟下一轮，不能宣称完整时间隔离或五秒撤销 SLA 达标。跨进程并发派发、严格一次副作用、积压保留和清理策略仍不是本轮验收范围。

管理员 TUN、跨机网络、三平台安装/签名/升级、用户搁置的人工试音、目标服务器完整容量以及许可证审核和正式 F/G/H/I 仍待完成。邮件保持可配置且默认关闭，不通过本修复变更外部渠道开关或安全期限。
