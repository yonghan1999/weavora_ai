# 需求规格说明书：织界

> 状态：客户端直传需求改基线候选，待重新人工审批。用户明确要求仅控制面与 Lighthouse、业务内容经虚拟局域网传输，并选择“客户端保存并在成员在线时同步，无在线副本时暂不可用”。已通过 CLI `rebaseline` 返回 B，历史 B/B1/B2/C 审批保留但不沿用。文中建议默认值和验收目标待本次批准，不代表已实现或实测。

## 产品目标

让异地朋友和固定游戏小队通过一个桌面工具完成长期群组交流、持久游戏房间组织、真实多人语音和真实虚拟局域网联机。用户进入房间后无需分别手工配置语音和网络，即可获取成员虚拟 IP 并在游戏中手动连接。

首版成功必须同时满足：

1. 账号、好友、群组、房间和权限由控制面持久化；消息正文、头像和附件由客户端持久化并通过授权在线副本同步。
2. 语音、游戏、文字、图片和视频均经真实虚拟局域网在客户端之间传输；控制面与 Lighthouse 不承载业务内容转发或存储。
3. 权限撤销、房间隔离、设备争抢和迟到连接处理不会造成越权或旧会话复活。
4. Windows、macOS、Linux 均为交付目标；只宣称实际验证的平台、系统版本和游戏版本。

首版不包含好友私聊、公开群搜索、游戏自动发现、普通互联网代理、物理局域网其他设备转发、支付或商业化管理。原始需求未定义独立封禁后台，本版仅处理封禁或账号失效导致的资格撤销事件。

仅直连，不部署或隐式启用 SFU、TURN、业务 Relay 和媒体服务器。Lighthouse 负责发现与打洞协调，不能保证所有 NAT/禁 UDP 网络可达；直连失败应明确显示。所有内容副本离线时暂不可用，最后副本丢失时不承诺恢复。账号控制、授权、必要信令、心跳、审计和更新仍有控制流量，不宣称服务器零流量。

## 用户故事或使用场景

1. **新用户**：使用邮箱注册并验证，登录后搜索账号、添加好友，通过有效邀请进入群组。
2. **群成员**：查看群资料、消息、在线成员和房间，向在线成员直传文字、图片和视频；本机已有历史可在有效权限下查看，缺少在线副本时显示暂不可用，并邀请朋友入群。
3. **群主或管理员**：管理成员、角色、邀请和本群全部房间，查看只读管理记录，处理群主转让或群组解散。
4. **房间管理者**：创建并配置长期房间，设置密码、房主和开放状态，开始或结束活动而不因活动结束删除房间。
5. **游戏成员**：加入房间后自动发起语音和虚拟网络连接，查看连接状态、复制自己的或成员的虚拟 IP，并在游戏内手动输入；在当前活动聊天发送文字、图片和视频。
6. **语音用户**：选择输入输出设备、测试设备、静音或关闭接收，调整总音量和成员音量，并处理设备拔出或权限拒绝。
7. **断线用户**：在保留期内恢复同一账号、设备、房间活动和原虚拟 IP；失效后按当前规则重新加入。
8. **切换设备或房间的用户**：目标可加入时保留旧活动，切换后旧资格失效；失败时不会出现两台设备同时活动，也不会由迟到结果复活旧活动。
9. **被移出或失权用户**：立即失去后续群内容同步、语音和虚拟网络权限，但可凭新的有效邀请按当前规则重新加入。
10. **跨平台小队**：Windows、macOS、Linux 用户在同一房间使用语音和虚拟网络；实际兼容性以支持矩阵中的已验证项为准。
11. **离线副本用户**：没有可达的授权副本时保留待同步或暂不可用状态；副本重新在线后按当前资格补同步，不能从旧副本恢复已删除或已结束活动的内容。

## 非功能需求

### 性能与容量

- 每房间最多 16 个不同账号，语音和虚拟网络均以 16 人为必测容量，而非仅界面容量。
- **建议验收目标**：在测试计划中明确的硬件、带宽和受控网络条件下，16 人语音、多人同时发言、虚拟网络与游戏并行持续 60 分钟，无崩溃、明显资源失控或权限失效。
- **建议验收目标**：服务端确认失权后 5 秒内完成语音、虚拟网络和同步撤销；该时间不是当前实测值。
- 测试须记录每端上下行、CPU/内存和文件传输并发；服务器只承担控制流量，16 人语音的客户端多路发送/接收成本不得忽略。大文件限速、背压且优先保障音频和游戏，具体带宽预算在 C/D 中确定。

### 可用性与恢复

- **建议默认值**：短暂断线保留 60 秒，保留房间名额、设备归属和原虚拟 IP；超时释放后按新加入处理。
- **建议验收目标**：网络恢复、对端可达且资格仍有效时，可用服务于 15 秒内自动恢复；失败可手动重试。语音依赖虚拟隧道，音频专属故障独立恢复。
- 切房和设备转移必须避免双活动；目标确认失败不得丢失仍可保留的旧活动，旧活动已结束后失败则保持未入房。
- 无服务端中继时不保证所有 NAT、CGNAT、禁 UDP 或防火墙环境可达；分别展示已加入、授权有效、隧道和各成员可达性，不将加入成功当作连接成功。禁止未授权悄悄启用流量中继。
- 无在线副本时显示暂不可用而非伪造空历史/成功；副本上线后按当前权限恢复。控制面或当前可信授权源失联超过可验证的授权期限后停止受控通信/读取，不无限离线沿用旧资格。

### 安全与隐私

- 敏感操作必须以服务端或当前可信授权源在执行时的资格为准，旧页面、旧令牌和旧连接不能继续授权。
- 房间之间进行网络、消息、管理记录和恢复资格隔离；安全测试覆盖水平越权和迟到事件。
- 认证凭据应使用行业通用安全存储与传输机制，具体算法和协议在架构阶段选型，本需求不预设技术栈。
- 普通日志和管理记录不得包含密码、验证码、令牌或秘密密钥；诊断信息须最小化敏感数据。
- 短期授权与活动代次须在受支持客户端的隧道及内容收发路径执行，撤销同时覆盖新连接、既有连接、后续分段和在途流。离线副本重连先同步权威删除/撤销再提供内容；长期网络证书、发现记录和客户端自报权限不能替代当前授权。
- 服务端元数据只包含必要身份、作用域、消息 ID/顺序、大小/类型、收据及删除审计，不接收正文、文件名敏感原文、头像或附件字节。接收端不信任发送端“已扫描”声明；媒体隔离探测与大小限制在收发端落实。
- 5 秒撤销针对产品受控路径及当前凭据；已下载副本无法远程保证抹除，不能阻止串通或修改过的客户端通过产品外渠道交换既有副本，不宣称实现该能力。

### 跨平台与可验证性

- 建议候选基线为 Windows 10 22H2/Windows 11 x64、macOS 13+（Intel 与 Apple Silicon）、Ubuntu 22.04/24.04 x86_64；待审批，其他平台不得被擅自宣称支持。
- 三平台互通与游戏自身跨平台能力分别记录；候选支持、已验证支持和未验证必须清晰区分。
- 发布证据须包含真实语音音频、真实虚拟网络 TCP/UDP 通信、权限异常、撤销隔离、并发争抢和长会话结果。
- 无法运行的平台、游戏或测试类别必须标为未验证及原因，不得以模拟结果替代真实核心能力验收。

### 数据与运维

- 产品内管理记录只读；后台防篡改、备份、物理删除、法定留存和恢复策略在架构及生产准备阶段另行确定。
- 更新不得破坏既有账号关联数据、群和房间配置；卸载行为不得被等同于删除服务端数据。
- 不编造法律结论、合规认证、兼容性或性能结果。

## 业务流程及关键状态

### 账号与设备

账号状态为“未验证 → 已验证；已明确失效为终止资格状态”。未验证只能注册验证、登录退出和找回密码。多端可同时登录，但房间活动资格绑定“账号 + 设备 + 房间活动代次”，同一账号全局最多一个活动房间和一台活动设备。

### 邀请与成员

待接受邀请可为“待接受、已接受、已撤销、已失效”。邀请默认不过期；群解散、邀请人退群或被移除使待接受邀请失效，重新入群不恢复旧邀请。接受操作必须幂等。已接受产生的成员关系独立存在，邀请人退群不影响该成员。被移出者凭新邀请重入时角色按默认普通成员处理，不恢复旧角色。

### 群主与房主

群主转让为“无转让 → 待指定成员接受 → 完成或取消/失效”，完成前原群主不变。群主退出必须选择已完成转让或解散。人工恢复申请只允许有证据的人工处理，争议时不变更。房主失去群籍或被封禁时由群主接管；普通离线、退房、凭据过期不接管。

### 房间与活动

房间开放状态为“开放、暂停”，生命周期为“可用、已删除”；活动状态为“无活动、活动中、结束中、已结束”。开放状态与活动状态独立：暂停阻止所有新加入但不清退现有成员；建议允许同活动保留期内的有效恢复，不视为新加入。结束活动保留暂停状态和房间配置，管理者须在房外重新开放。删除房间为终态并取消全部恢复。

### 加入、切换与恢复

加入成功创建活动资格并自动建立虚拟网络，隧道就绪后启动语音。切房/设备转移采用“校验目标并保留旧活动 → 确认目标资格可加入 → 撤销旧授权/完成屏障 → 激活新资格 → 建立隧道与语音”；资格可加入不保证 NAT 可达。目标资格校验失败且旧活动仍有效时保留旧活动；切换已提交后连接失败不复活旧活动。各环节按代次拒绝迟到结果。

### 语音与虚拟网络

两项各自具有“未连接、连接中、已连接、受限、断开、重试中、失败”等真实状态。语音增加等待隧道/部分成员不可达提示；隧道故障可影响语音，音频故障不停止隧道，结束或失权两项均终止。群内容通过独立授权的应用范围同步，不以入房为条件，也不授予跨房游戏或语音通信资格。

### 消息与群组解散

消息为“可见、已删除”，删除保留提示而非恢复原内容。管理记录只能追加和按权限读取。群解散后产品内群、消息、房间、邀请和管理记录均不可查看或恢复，后台物理处理另按批准政策执行。

### 真实消息、上传与撤销

群消息发送/读取要求当前有效群籍。房间消息要求当前账号/设备持有已激活且未过期的活动资格，断线 grace 不允许从无效连接继续发送；成功恢复同活动后可补读当前活动历史。房主不能凭房主身份在未入房时读取房间聊天；群管理员同样须加入活动才能读取房间消息，管理记录权限不因此扩大为消息旁路。群主/管理员仅在有权访问的房间活动中可代删，房间房主不额外获得删除他人消息权。

传输状态为“本机校验 → 本机保存/待同步 → 传输中 → 对端校验并持久化 → 对端已接收”，附取消、失败、部分送达、暂不可用和重试。元数据登记成功不能标已送达；无其他在线成员仅标本机保存/待同步。至少一个授权对端确认完整内容校验与落盘后才显示对端已接收，剩余收件人状态单独展示，不能暗示所有成员送达。

控制面为当前作用域登记不可猜测消息 ID、单调序号、作者、内容摘要引用和 tombstone，不收正文。接收端验证授权、完整性、字节范围与消息 ID 幂等，同一发送只生成一条消息；乱序按权威序号收敛，缺失内容显示待同步。过期、失权、撤销和活动结束禁止迟到提交；撤销可见性、逻辑配额预留/释放和成功确认在 C 中设计原子边界。收到对端落盘确认前不提交“已送达”；收据丢失按同键查询/重试，不重复创建。

关闭表单/切页不默认发送，取消中止尚未确认的传输并撤销预留；已提交的消息须走删除流程，不能通过取消伪装撤回已接收副本。超过 15 分钟的未提交草稿不能首次提交，已提交但尚未对某端送达的消息按当前有效引用续传，不重新变成过期草稿。每次发送和补读均校验当前群/活动资格，不能挪用其他范围附件。媒体等待/失败不停止可用隧道与语音。

作者可删除自己的群/当前活动消息，群主/管理员可按上述当前范围代删；删除文字与媒体均显示提示，管理员代删追加只读记录。退房/被踢结束房间聊天读取与上传，仍有效群籍保留群聊天权；退群/移出群撤销该群全部消息/媒体资格；结束活动清除活动历史读取和上传，新活动不继承附件；解散群/账号失效撤销相应后续同步与访问。不能用旧游标、旧下载链接、Range 重试或迟到上传完成绕过，服务端确认后沿用 5 秒撤销目标。

离线副本上线必须先取得当前控制面授权及删除/活动快照再提供历史；被删除的旧内容不得反向恢复。无在线副本不伪造空历史，也不保证找全从未取得的内容；元数据可显示缺口但不代表存在可用副本。

## 异常场景与边界条件

1. 未验证用户访问群、邀请、房间、消息、语音或虚拟网络时被拒绝；过期验证码、错误密码和已验证邮箱找回按账号规则处理。
2. 重复好友申请、重复接受邀请、重复加入、重复退房和并发管理操作必须幂等或返回明确冲突，不产生重复关系。
3. 第 16 个不同账号可加入，第 17 个被拒绝；断线保留账号也占名额，名额释放后才能接纳新账号。
4. 暂停时所有新加入均被拒，包括管理员；现有成员不被清退，保留期内恢复与新加入分开校验。
5. 管理员免密码但不免人数、暂停、群籍、账号状态或设备活动资格；房主权限不扩张为群权限。
6. 修改房间密码不清退现有成员；被踢者可在没有额外封禁时按当前规则主动重入。
7. 切房、设备转移和并发加入出现竞争时，不得双活动、超额、错误占位或由旧代次结果复活。
8. 网络中断短于或超过建议 60 秒保留期分别处理；超时后原 IP 不保证，恢复仍须检查账号、群籍、活动资格、名额和设备；重新加入时在地址可用且无冲突的前提下优先尝试原 IP，失败则分配新地址。
9. 虚拟隧道故障影响依赖该路径的语音和内容传输，按成员显示受限/断开；音频设备或语音专属故障不停止隧道，可独立重试。
10. 麦克风/输出权限拒绝、设备拔出、默认设备变化、地址冲突、虚拟网卡权限不足和连接失败均有可理解提示。
11. 退出、踢出、退群、失权、账号失效、结束活动或删除房间与在途连接同时发生时，撤销优先，迟到成功结果无效。
12. 成员删除本人消息与管理员代删记录区别展示；非当前群主或管理员不得读取管理记录，跨群访问必须失败。
13. 控制面重启后持久元数据仍在；客户端重启后本机已保存消息仍在，缺失正文依赖可达授权副本；群解散后产品内不可恢复，不等于物理抹除。
14. 不支持或未测试的系统、架构、桌面环境和游戏必须显示未验证，而不是伪造兼容。
15. 邮件服务、系统授权、签名证书或测试设备不可用时，相关项目标记未验证并记录影响，不能转成模拟通过。
16. 伪造扩展名、超大/截断文件、解压/解码资源耗尽、超分辨率/超时长视频、路径穿越及脚本内容应被拒绝且不公开临时对象；文件名与消息正文须转义，媒体探测不能执行用户命令。
17. 并发上传预留与发送遇到配额上限、磁盘水位不足、断网、服务重启或清理竞争时，不产生重复消息、超配额、幽灵已发送或无权限可读附件。校验失败不记录原文件内容或带凭据的 URL。
18. 上传中发生切房、设备转移、踢出、结束活动、删除消息或解散群时，以服务端当前代次和资格为准，迟到完成不能生成消息或复活访问；其他群和仍有效通道不受无关清理影响。
19. 所有副本离线、对端 NAT 不可达、本机磁盘满、收据丢失、乱序、重复同步和最后副本丢失分别处理；不得自动改走服务器上传或用本机预览伪造送达。
20. 控制面失联时到期授权不能续用；旧副本上线先同步 tombstone 和资格，不能复活已删除历史或已结束活动。

### 基线覆盖检查

- 功能需求：REQ-001～REQ-029，共 29 项。
- 验收标准：AC-001～AC-048，共 48 项。
- 每项功能需求至少有一项验收标准；架构、任务和测试阶段必须沿用这些标识，不得另建无追踪需求。
- 待审批建议：候选系统基线、60 秒断线保留、5 秒撤销目标、15 秒恢复目标、60 分钟长会话目标及封禁范围解释。
- 后续专项设计：邮件渠道、虚拟网卡与权限、Lighthouse/隧道具体引擎和版本、直连探测、客户端语音协议、短期授权/撤销屏障、内容副本发现/同步、本地存储、签名证书及安装。无服务端业务中继是明确约束，不留作自动回退。
- 本次待批准默认值：单对端持久接收判据、10 GiB 逻辑引用预算、本机磁盘满拒收、15 分钟未提交草稿、24 小时本机运行/启动清理规则，以及长期授权失联不可无限使用。均已写成可核对的条款，不能把用户选择存储方向等同于人工批准这些默认细节。

- 变更来源：用户要求只保留控制面和 Lighthouse，随后明确选择“客户端保存并在成员在线时同步；无在线副本时显示暂不可用”。这授权准备本次基线，不代替 CLI 人工审批。
