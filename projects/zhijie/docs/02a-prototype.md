# 产品原型设计：织界

> 状态：B1 产品原型基线候选。依据已批准的 `docs/02-requirements.md`（REQ-001～REQ-024）。本阶段只确认功能结构、操作流程、权限和状态；不验证真实语音、虚拟网络、性能、安全、邮件投递或平台兼容性。

## 设计目标与范围

织界桌面端以“群组”为长期协作空间，以“房间”为持久联机配置，以“活动”为一次临时联机会话。用户加入房间活动后，界面并行展示语音与虚拟网络的独立连接过程，并提供成员虚拟 IP 供其在游戏中手动连接。

首版原型覆盖邮箱账号、好友、私密群组、邀请与群主治理、角色权限、持久房间、16 人容量、加入/切房/设备转移、断线恢复、真实能力的状态表达、消息、只读管理记录及支持矩阵。明确不提供好友私聊、公开群搜索、游戏自动发现、互联网代理、物理 LAN 转发、支付和独立封禁后台。

根据用户反馈，原型从企业后台式分页结构调整为面向 C 端的 Discord 式社交工作区：左侧群组图标栏、频道/房间栏、中间聊天或活动区、右侧成员/IP 区，并在频道栏底部常驻语音与用户控制。用户无需离开聊天即可看到房间、在线成员和连接状态；管理功能收进群管理区，设置和危险操作使用对话框。深色和紫色仅用于确认社交信息层级与风格方向，最终配色、字体、图标和组件外观仍在 B2 评审。

## 页面结构

```text
未认证区
├─ 登录
├─ 注册 → 邮箱验证码
└─ 找回密码 → 已验证邮箱重置

已认证桌面壳
├─ 首页
│  ├─ 当前活动摘要
│  ├─ 待办邀请/好友申请
│  └─ 服务、语音、网络状态
├─ 好友
│  ├─ 好友列表与在线状态
│  ├─ 账号搜索/申请
│  └─ 收到的申请
├─ 群组图标栏 → 群组社交工作区
│  ├─ 频道/房间栏
│  │  ├─ 文字频道：大厅闲聊、邀请与组队
│  │  ├─ 游戏房间：人数、房内成员、加入与活动详情
│  │  ├─ 群管理：房间、成员、邀请、管理记录和群设置
│  │  └─ 常驻底部：语音/网络摘要、断开、静音、接收和账号设置
│  ├─ 中间主内容
│  │  ├─ 聊天消息与发送框
│  │  └─ 房间活动：独立语音/网络状态、切房、设备转移与恢复
│  └─ 右侧成员区：在线/离线、说话状态、活动成员与虚拟 IP
├─ 兼容性与帮助
└─ 账号与设备
```

群组图标栏只切换账号级页面和已加入群组；群内容必须经有效群籍进入。日常聊天、房间、成员与语音控制同屏，减少页面跳转。房主管理入口位于房间上下文，不提升群角色；管理记录与普通消息分离，避免把审计操作误解为可编辑消息。

## 核心流程

### 1. 注册、登录与找回

注册邮箱 → 提交验证码 → 成为已验证账号 → 登录进入首页。未验证时访问群、好友或房间会显示资格拒绝并返回账号页。找回密码只通过已验证邮箱；重置完成后返回登录，不显示任何秘密。

### 2. 好友与入群

搜索账号 → 发送好友申请 → 对方接受/拒绝 → 好友列表更新。当前群成员从好友或账号搜索发起群邀请 → 被邀请人在首页接受 → 群成员关系幂等创建。好友关系本身不提供群或房间权限。

### 3. 创建并加入活动

群主/管理员创建持久房间 → 设置游戏、密码、房主和开放状态 → 开始活动 → 成员加入。加入时依次校验当前账号、群籍、密码或管理员豁免、暂停状态、16 人容量及全局设备活动资格；成功后并行发起语音和虚拟网络连接，不等待其中一项成功再启动另一项。

### 4. 游戏内手动联机

活动中 → 查看自己的虚拟 IP 或成员 IP → 复制 → 在游戏内手动输入。界面明确“不依赖广播发现”；不宣称自动发现游戏、代理互联网或转发物理 LAN。

### 5. 切房与设备转移

从当前活动选择目标房间/新设备 → 目标预检并保留旧活动 → 目标确认可加入 → 原子切换 → 旧资格失效并分别连接。目标失败且旧活动仍有效时留在旧活动；旧活动已结束则显示未入房。任何迟到成功提示均不能恢复旧活动。

### 6. 断线与独立恢复

语音和网络分别显示连接中、已连接、受限、断开、重试中和失败。短时断线进入 60 秒保留，显示同账号同设备恢复及原 IP 保持规则；超时后名额释放。语音失败可独立重试且网络继续，反之亦然。主动退出、切房、失权、结束或删除立即取消恢复。

### 7. 房间与群治理

结束活动 → 清退成员并终止语音/网络 → 保留房间配置及暂停状态。删除房间 → 全部会话和恢复终止。群主转让 → 指定成员接受前原群主不变。群主退出 → 必须选择已完成转让或解散。解散 → 群、消息、房间、邀请和管理记录在产品内不可查看或恢复。

## 角色与权限

| 操作 | 普通成员 | 房间房主 | 群管理员 | 群主 |
| --- | --- | --- | --- | --- |
| 邀请用户 | 可以 | 按其群角色 | 可以 | 可以 |
| 撤销待接受邀请 | 不可以 | 不因此获得权限 | 可以 | 可以 |
| 修改群资料/管理普通成员 | 不可以 | 不因此获得权限 | 可以，但不能管理群主或同级 | 可以 |
| 查看管理记录 | 不可以 | 不因此获得权限 | 可以 | 可以 |
| 创建房间 | 不默认允许 | 不额外获得 | 可以 | 可以 |
| 管理本人房间 | 被指定为房主时可以 | 可以 | 可以管理本群房间 | 可以 |
| 指定房主 | 不可以 | 不因此获得群权限 | 按群管理规则 | 可直接指定有效成员 |
| 转让/解散群 | 不可以 | 不可以 | 不可以 | 可以 |
| 免房间密码 | 不适用 | 按房间规则 | 可以 | 可以 |
| 绕过容量、暂停、群籍或账号状态 | 不可以 | 不可以 | 不可以 | 不可以 |

原型提供“模拟当前身份”切换，仅用于走查按钮可见性与拒绝提示，不代表客户端拥有授权决定权。实际实现必须在每次敏感操作执行时重新校验当前资格；失权后旧页面、旧会话和旧连接均不可继续操作。

## 关键状态与异常

| 类别 | 原型表达 |
| --- | --- |
| 加载与连接 | 服务、语音、网络分别展示连接中/重试中，不使用全局一个“成功”覆盖分域状态 |
| 空状态 | 无好友、无群、无房间、无消息、无管理记录时说明下一步，不伪造内容 |
| 未验证/失权 | 拒绝进入业务内容；失权后停止同步、语音、网络及恢复并返回可理解页面 |
| 邀请冲突 | 重复接受幂等；撤销、邀请人退群/被移除、群解散使待接受邀请失效 |
| 群主治理 | 未转让不得退出；接受前归属不变；恢复证据不足或争议不改变归属 |
| 容量与开放 | 第 16 人可加入，第 17 人被拒；断线保留占额；暂停对管理员同样生效 |
| 房间密码 | 管理员可免密码但不能绕过其他校验；改密码不清退现有成员；被踢不封禁 |
| 切换竞争 | 明确保留旧活动或变为未入房；不显示双活动，不接受旧代次迟到结果 |
| 断线恢复 | 60 秒内同账号同设备恢复并保持原 IP；超时按新加入处理 |
| IP 重入 | 不承诺原 IP；安全、可用且无冲突时优先尝试，否则分配新地址并建立全新授权 |
| 音频异常 | 权限拒绝、设备拔出/切换、连接失败均提示并可重试；不无故停止网络 |
| 网络异常 | 地址冲突、系统权限不足、TUN/中继失败分别提示；不伪造已连接 |
| 消息删除 | 本人删除与管理员代删显示不同提示；代删追加管理记录 |
| 危险操作 | 结束活动、删除房间、退出/解散群使用确认对话框，说明影响与不可逆边界 |
| 平台兼容 | 候选与验证状态分列；当前没有实机结果时统一标为未验证 |

## 设计假设与待确认事项

1. 采用“群组图标栏 + 频道/房间栏 + 主内容 + 成员区”的桌面四区结构和常驻语音控制，属于用户明确要求参考的 C 端 Discord 式方向，仍待 B1 人工确认；窄窗口隐藏成员区、更小窗口收起频道栏。B2 才可确定最终视觉。
2. 原型提供身份与故障场景切换以便走查，不是正式用户功能；开发时应放入测试工具，不向普通用户暴露。
3. 断线保留 60 秒、失权撤销 5 秒、服务恢复 15 秒和长会话 60 分钟均沿用已批准需求的验收目标，不是实测结果。
