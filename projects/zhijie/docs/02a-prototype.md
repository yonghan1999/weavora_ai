# 产品原型设计：织界 WEAVORA

> 品牌名称：中文为“织界”，英文统一使用“WEAVORA”，不再使用“ZHIJIE”作为产品英文标识。内部工作流项目标识 `zhijie` 仅用于文件与审批追踪，不属于产品品牌。

> 状态：B1 产品原型基线候选。依据已批准的 `docs/02-requirements.md`（REQ-001～REQ-024）。本轮按用户明确反馈彻底放弃 KOOK / Discord 式频道工作区，以游戏玩家的组队、语音、文字和虚拟局域网联机为核心。原型只验证模拟界面路径，不验证真实语音、虚拟网络、性能、安全、邮件投递或平台兼容性。

## 设计目标与范围

织界桌面端以“玩家大厅”为日常入口，以“游戏房间”为组队与联机核心，以“私密群组”为长期社交关系。主任务不是浏览频道，而是回答三个问题：**谁在玩、下一局去哪、怎样马上连上**。

本轮视觉采用炭黑、荧光黄绿、游戏房卡片与玩家语音头像，区别于此前 KOOK 参考方案的绿色频道栏和 Discord 式紫蓝配色。高保真外观用于帮助确认产品方向，最终设计令牌、组件细节与跨平台适配仍在 B2 确认。

首版仍覆盖邮箱账号、好友、私密群组、邀请与群主治理、角色权限、持久房间、16 人容量、单设备活动、断线恢复、独立语音/网络状态、消息、只读管理记录和支持矩阵。明确不提供好友私聊、公开群搜索、游戏自动发现、互联网代理、物理 LAN 转发、支付和独立封禁后台。

### 核心产品决策

1. **大厅优先于频道**：登录直达玩家大厅，首屏展示当前队伍、可加入游戏房间和在线好友，不设置多栏频道树。
2. **房间就是主战场**：玩家头像和说话状态占据主区域；聊天、联机和成员是房间右侧三个并列页签。
3. **入房后语音始终触手可及**：未加入房间时底部语音条完全隐藏且不占布局空间；加入后跨大厅、好友、群组和房间持续显示，可静音、关闭接收、调整设备或离开，退出房间后再次隐藏。开麦不等于正在发言，只有独立语音活动状态成立时才显示“发言中”和声波。
4. **联机只做必要三步**：确认实际游戏主机成员并复制其虚拟 IP → 游戏内选择直接连接 → 粘贴地址。网络细节不混入社交成员列表。
5. **社交与管理分层**：好友和群组有独立导航；群成员、邀请、角色、只读管理记录和危险操作收进群组管理对话框。
6. **状态不互相冒充**：语音与虚拟网络分别连接、分别失败、分别恢复；任何延迟、在线或兼容状态均为模拟展示，不作为真实能力证据。
7. **设置导航保持一致**：语音与设备、账号与设备、安装与支持统一使用左侧页签、右侧内容的页内切换，不在同级页签之间混用弹框；设备、音量和偏好跨页签保留。只有设备转移等需防误触的确认步骤使用对话框。

## 页面结构

```text
未认证区
├─ 登录 → 玩家大厅
├─ 注册 → 邮箱验证码 → 玩家大厅
└─ 找回密码 → 已验证邮箱重置

已认证桌面壳
├─ 顶部：产品标识 / 模拟数据标识
├─ 左侧主导航
│  ├─ 大厅：当前活动（仅入房后）+ 游戏房卡片 + 在线好友
│  ├─ 好友：筛选、昵称/账号 ID 搜索、资料卡、申请与组队邀请
│  ├─ 群组：私密群组卡片 → 长期群聊 → 群组管理
│  ├─ 创建：创建持久游戏房间
│  └─ 设置：语音设备、账号设备、安装支持、退出
├─ 游戏房间
│  ├─ 主区域：玩家头像、房主、说话与静音状态、邀请队友
│  └─ 右侧页签：聊天 / 联机 / 成员
└─ 入房后的常驻语音条
   ├─ 当前房间与双通道摘要
   ├─ 静音 / 关闭接收 / 设备 / 离开
   └─ 独立网络连接状态
```

全局搜索、通知中心、拓扑动画和无真实探测的精确延迟不在首版原型展示。所有房间、成员、房主、IP、好友关系、群人数与消息均由统一模拟数据派生，操作后同步更新页面。

窄窗口优先收起大厅右侧好友栏；900 px 及以下房间改为玩家区在上、聊天/联机/成员区在下，600 px 及以下主导航转为底部横向布局并保留设置与账号入口。移动端属于布局适配示意，不代表原生移动端或完整平台兼容性承诺。

## 核心流程

### 1. 注册、登录与找回

注册邮箱 → 提交验证码 → 成为已验证账号 → 登录直达玩家大厅。未验证时不能访问好友、群组或房间。找回只通过已验证邮箱，不提供人工绕过入口。

### 2. 好友与群组

搜索账号 → 发送好友申请 → 对方接受/拒绝 → 更新好友列表。点击好友资料卡可复制账号 ID 或邀请组队；首版无私聊。群组只通过私密邀请进入，长期保存消息和房间。当前群成员可邀请，撤销待接受邀请仅群主/管理员。

### 3. 快速组队与加入

大厅点击“快速组队” → 填写房间、游戏、容量和可选密码 → 创建并进入。加入已有房间时校验群籍、开放状态、16 人容量、密码/管理员豁免及全局设备活动资格。成功后并行发起语音与虚拟网络连接。

### 4. 房间语音与文字

进入房间 → 玩家头像展示说话、静音与连接状态 → 底部语音条随时控制本地设备 → 右侧“聊天”发送房间文字。成员音量只影响本地接收，关闭接收不修改其他成员设置。

### 5. 游戏内手动联机

房间右侧“联机” → 确认实际游戏主机成员并复制其虚拟 IP → 游戏内选择“直接连接 / 输入 IP” → 粘贴地址。界面明确不依赖广播发现，不自动发现游戏，不代理互联网，不转发物理 LAN。

### 6. 离开、切换与恢复

退出会撤销本次语音、虚拟网络、旧恢复和设备活动资格，持久房间保留。切房/设备转移先预检目标并保留仍可用的旧活动，再原子替换，任何时刻不双活动。短时断线在 60 秒保留期内以同账号同设备恢复并保持原 IP；超时重入按新会话处理，安全可用时优先尝试原地址。

### 7. 房间与群治理

结束活动清退成员并终止语音/网络但保留房间配置及暂停状态；删除房间终止全部会话和恢复。群主转让须指定成员接受；群主退出前必须完成转让或解散。解散后产品内不可查看或恢复群、消息、房间、邀请和管理记录。

## 角色与权限

| 操作 | 普通成员 | 房间房主 | 群管理员 | 群主 |
| --- | --- | --- | --- | --- |
| 邀请用户 | 可以 | 按其群角色 | 可以 | 可以 |
| 撤销待接受邀请 | 不可以 | 不因此获得权限 | 可以 | 可以 |
| 修改群资料/管理普通成员 | 不可以 | 不因此获得权限 | 可以，但不能管理群主或同级 | 可以 |
| 查看管理记录 | 不可以 | 不因此获得权限 | 可以 | 可以 |
| 创建房间 | 不默认允许 | 不额外获得 | 可以 | 可以 |
| 管理本人房间 | 被指定为房主时可以 | 可以 | 可以管理本群房间 | 可以 |
| 指定房主 | 不可以 | 不因此获得群权限 | 按群管理规则 | 可直接指定有效成员 |
| 转让/解散群 | 不可以 | 不可以 | 不可以 | 可以 |
| 免房间密码 | 不适用 | 按房间规则 | 可以 | 可以 |
| 绕过容量、暂停、群籍或账号状态 | 不可以 | 不可以 | 不可以 | 不可以 |

“模拟当前身份”只用于走查按钮可见性与拒绝提示，不属于正式用户能力。真实实现必须在敏感操作执行时重新校验当前资格。

## 关键状态与异常

| 类别 | 原型表达 |
| --- | --- |
| 加载与连接 | 服务、语音、网络分别表达，不用一个全局成功覆盖所有分域 |
| 空状态 | 未入房、无搜索结果等提供下一步，不伪造玩家或消息 |
| 未验证/失权 | 拒绝进入业务内容；失权后停止同步、语音、网络及恢复 |
| 邀请冲突 | 重复接受幂等；撤销、邀请人失去群籍或群解散使邀请失效 |
| 群主治理 | 未转让不得退出；接受前归属不变；恢复不自动继任 |
| 容量与开放 | 第 16 人可加入，第 17 人被拒；断线保留占额；暂停对管理员同样生效 |
| 房间密码 | 管理员可免密码但不能绕过其他校验；改密码不清退现有成员 |
| 切换竞争 | 保留旧有效活动或显示未入房，不显示双活动，不接受迟到旧结果 |
| 断线恢复 | 60 秒内同账号同设备恢复并保持原 IP；超时按新加入处理 |
| IP 重入 | 不承诺原 IP；安全可用且无冲突时优先尝试，否则分配新地址 |
| 音频异常 | 权限拒绝、设备拔出/切换和连接失败分别提示并独立重试 |
| 网络异常 | 地址冲突、系统权限不足和连接失败分别提示，不伪造已连接 |
| 消息删除 | 本人或管理角色可删除，确认后原位置保留提示；真实代删记录由后续实现追加 |
| 危险操作 | 离开、结束、删除、退出/解散均须确认影响和不可逆边界 |
| 平台兼容 | 候选与验证状态分列；当前无实机结果时统一标为未验证 |

## 设计假设与待确认事项

1. “玩家大厅 + 游戏房间 + 常驻语音条”替代此前的四栏频道工作区，是本轮最重要的待确认产品方向。

6. 群解散、物理删除、备份和法定留存是不同事项；本原型只表达产品内不可恢复。
