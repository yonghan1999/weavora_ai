# 需求接收：织界

## 初始想法与背景

为散落各地的朋友和固定游戏小队提供跨 Windows、macOS、Linux 的桌面工具，首版同时实现邮箱账号、基础好友、长期群组与房间、文字聊天、最多 16 人真实语音和真实虚拟局域网。用户进入游戏房间后自动连接语音和虚拟网络，可查看、复制成员虚拟 IP，并在游戏中手动输入虚拟 IP 联机。

原始需求全文保存于 `docs/00-original-requirements.txt`。真实语音和真实虚拟网络均为不可降级的核心能力，不能用界面、模拟状态或演示数据替代。

## 当前已知条件

- 项目名称：织界；工作流标识：`WF-zhijie`。
- 群组是长期交流空间，房间是长期保存的配置对象，本次游戏活动是临时会话，三者不得混淆。
- 首版包含邮箱注册验证、登录退出、找回密码、基础好友、群组、角色、文字聊天、历史消息、长期房间和权限管理。
- 每个房间最多 16 个不同账号，断线保留期内仍占名额。
- 语音支持 16 人、设备选择、独立音量、静音、设备测试和异常恢复。
- 虚拟网络按房间隔离，每位有效活动成员拥有当前活动内唯一虚拟 IP；首版手动 IP 联机，不依赖游戏广播发现。
- 语音和虚拟网络独立连接、独立展示状态，单项失败不应无故中断另一项。
- 退出、切房、被踢、失权、结束活动或删除房间后，连接、恢复资格和后续内容同步必须撤销。
- 三平台均为产品目标；候选支持与已验证兼容必须区分，未测试不得宣称兼容。
- 默认只进行研发与验证，不擅自部署生产、购买资源、提交代码或修改分支。

## 待澄清问题

以下作为需求基线的建议决策提交审批，而非用户已确认事实：

1. **候选系统基线**：建议 Windows 10 22H2/Windows 11 x64、macOS 13+（Intel 与 Apple Silicon）、Ubuntu 22.04/24.04 x86_64。三平台不缩减，其他系统或架构只列候选，未验证不宣称支持。
2. **断线保留默认值**：建议 60 秒。保留账号名额、设备归属和原虚拟 IP；超过时限释放名额，重新加入按新加入处理且不承诺原 IP。该值须通过网络扰动测试调整或确认。
3. **建议质量目标**：在明确的受控网络与硬件条件下，16 人语音及游戏并行持续 60 分钟；权限撤销在服务端确认后 5 秒内生效；短时网络恢复后 15 秒内完成可用服务恢复。以上均为验收目标，不是实测结果。
4. **“封禁”范围**：原始规则引用封禁和账号失效事件，但未定义独立封禁管理后台。首版草案仅要求在这些资格失效事件发生时撤销权限，不新增未明确要求的封禁管理产品。
5. **数据物理删除政策**：群解散后的产品内不可见、不可恢复属于首版功能；备份、物理删除和法定留存须在生产前另行制定，不在本需求中作法律结论。
6. **游戏验证矩阵**：具体游戏及版本尚未指定。首版以真实 TCP/UDP 服务和手动虚拟 IP 联机验证核心网络，发布时只能列出实际测试的游戏版本；工具互通不等于游戏支持跨平台。

## 初步范围及风险

### 初步范围

账号与好友、私密群组与邀请、角色权限、长期房间与临时活动、文字消息、管理记录、真实多人语音、真实虚拟局域网、断线恢复、撤销隔离、三平台安装更新卸载及验证矩阵。首版明确不做好友私聊、公开群搜索、游戏自动发现、普通互联网代理、物理局域网转发或生产部署。

### 初步风险

- 三平台虚拟网卡、路由、权限、签名和安装卸载差异较大，需要真实系统权限和测试设备。
- NAT 穿透、中继、16 人语音并发、长会话和网络扰动可能影响容量与质量，必须实测。
- 房间资格、设备归属、活动代次和迟到连接结果处理不当，可能造成越权或旧会话复活。
- 邮件验证与找回密码需要可用邮件发送渠道；缺少外部账号时相关真实端到端验证会受限。
- 虚拟网络可能需要管理员/root 授权、系统扩展或签名证书；缺少时会影响安装和真实网络验证。
- 首版范围较大，可分阶段实施网络后语音，但发布验收不得省略任一核心能力。
