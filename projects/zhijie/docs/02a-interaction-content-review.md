# 织界 WEAVORA：交互逻辑、展示数据与初版范围评审

> 性质：设计分析文档，不替代已批准需求与 B1 原型基线。依据 `02-requirements.md` 和当前客户端原型整理。
>
> “数据来源”指逻辑上的权威来源，不预设具体技术栈或服务拆分。“初版必要”依据已批准 REQ-001～REQ-024，而不是根据当前原型是否已经完成。

## 1. 总体结论

当前“玩家大厅 → 游戏房间 → 语音与虚拟局域网联机”的方向合理，但原型仍存在展示数据各自硬编码、连接状态与实际操作不一致、部分操作只提示成功而不更新模拟状态的问题。

后续应遵循三条原则：

1. **同一事实只有一个权威来源**：房间、游戏、房主、成员、IP、好友在线状态不能在不同页面分别填写。
2. **界面只展示当前已经发生的事实**：连接中不能显示已连接，未分配 IP 不能展示可用地址，模拟成功不能冒充真实成功。
3. **初版优先完成核心闭环，不堆装饰能力**：账号、好友、群组、房间、消息、语音、虚拟网络、权限与恢复是必须项；全局搜索、通知中心、网络拓扑动画、房间封面和精确延迟可以删减或延后。

## 2. 全局交互状态与页面规则

### 2.1 房间主状态链

```text
未入房 idle
  → 点击加入
  → 校验中 validating
  → 创建活动资格
  → joining（语音、网络分别连接）
  → 已入房 active
  → reconnecting（短时断线保留）
  → active 或释放后回到 idle

active → leaving → idle
active → 切房/设备转移预检 → 原子切换 → 新 active
active → 失权/结束/删除 → idle（禁止旧会话复活）
```

### 2.2 页面必须统一遵守的展示规则

| 状态 | 大厅 | 底部语音条 | 房间页 | 联机页 |
| --- | --- | --- | --- | --- |
| 未入房 | 可展示房间本身是否进行中和成员数，但不能展示“我已连接” | 完全隐藏，不占空间 | 可查看公开给当前群成员的房间信息与加入条件 | 不展示本人 IP；不可声称已连接 |
| 校验/加入中 | 显示取消或进度，不重复提交 | 可显示连接进度，也可在进入动画后出现；需统一 | 显示资格与双通道连接过程 | 语音、网络分别显示连接中，IP 未分配则为空 |
| 已入房 | 显示“回到房间”和真实连接时长 | 持续显示，跨页面保留 | 显示成员、聊天、语音与网络状态 | 显示已分配 IP 和复制入口 |
| 语音失败、网络成功 | 网络可继续使用 | 显示语音失败与独立重试 | 语音区域失败，网络区域正常 | IP 仍可用 |
| 网络失败、语音成功 | 语音可继续使用 | 显示网络失败与独立重试 | 语音区域正常，网络区域失败 | 不显示“LAN 已就绪”；按实际情况保留或隐藏地址 |
| 断线保留 | 显示恢复进度和剩余时间 | 显示重连状态 | 保留活动身份，不伪造已恢复 | 有效恢复期间保持原 IP |
| 离开/失权/结束 | 移除个人活动信息 | 隐藏 | 返回到可加入或无权限页面 | 撤销旧地址与复制入口 |

### 2.3 语音状态的独立口径

- 麦克风开启只显示“已开麦”，不等于“正在发言”。
- “正在发言”和声波必须来自实际音频活动事件，不能由 `muted = false` 推导。
- 关闭接收只影响本地收听；成员独立音量只影响本地，不修改他人设置。
- 语音连接、虚拟网络连接和账号在线是三个不同状态，不能共用一个绿色圆点代替。

## 3. 数据来源类型

| 类型 | 内容 | 权威性与注意事项 |
| --- | --- | --- |
| 账号与权限数据 | 账号、邮箱验证、好友关系、群籍、角色、邀请、设备活动资格 | 以服务端或当前可信授权源为准；旧页面和旧令牌不能继续授权 |
| 持久业务数据 | 群组、房间配置、消息、管理记录 | 服务重启后仍需保持；客户端只能请求，不可本地伪造持久化成功 |
| 实时活动数据 | 活动成员、保留名额、当前房间、活动代次、语音连接与说话状态 | 以当前活动和设备资格为边界；迟到事件必须按代次丢弃 |
| 虚拟网络代理数据 | 本人/成员虚拟 IP、分配状态、连接状态、冲突与权限错误 | 只有真实分配与探测结果才能驱动成功展示；不能由前端随机生成 |
| 本地设备数据 | 输入输出设备、静音、关闭接收、总音量、成员音量、设备权限 | 来自操作系统和本地音频组件；成员音量是本地偏好，不上传为他人配置 |
| 派生展示数据 | 在线人数、房间人数、连接时长、成员拓扑、聚合服务状态 | 由权威数据计算，不应再维护一套手工数字 |
| 发布维护数据 | 系统支持矩阵、安装说明、游戏验证状态、帮助文档 | 由发布与测试结果维护；候选、已验证、未验证必须区分 |
| 用户填写数据 | 房间名、游戏名、简介、密码、邀请附言 | 游戏名首版手动填写，不依赖游戏自动发现或第三方资料库 |

## 4. 逐页评审

### 4.1 登录、注册、找回密码

| 项目 | 合理交互与展示 | 数据来源 | 初版是否必要 |
| --- | --- | --- | --- |
| 邮箱登录/退出 | 提交后显示处理中、失败原因和成功跳转；不能点击即假装成功 | 账号认证与验证状态 | **必须** |
| 注册与验证码 | 发送、重发、过期、错误、验证成功状态完整 | 邮件投递结果与账号验证状态 | **必须** |
| 找回密码 | 只通过已验证邮箱，不能提供人工绕过入口 | 已验证邮箱与重置流程状态 | **必须** |
| 默认已入房场景 | 只能用于“返回用户”演示，不能作为所有用户登录后的必然状态 | 当前账号活动资格 | 演示可选；真实实现必须查询 |

**当前修正点**：原型登录直接恢复已入房状态，只适用于预设演示，不应被理解为通用产品规则。

### 4.2 玩家大厅

| 展示/交互 | 合理性与口径 | 数据来源 | 初版是否必要 |
| --- | --- | --- | --- |
| 可加入房间列表 | 核心入口；显示名称、游戏、开放/活动状态、人数和加入条件 | 当前账号可见群组的房间、活动与资格 | **必须** |
| 当前活动卡片 | 仅在本人确有活动时显示“回到房间”和连接信息 | 当前设备活动资格、房间与连接状态 | **必须，条件显示** |
| 房间人数 `x/16` | 统计不同账号，包含断线保留名额；不是简单头像数 | 活动成员与保留记录，派生计数 | **必须** |
| 在线好友摘要 | 不应包含自己；状态与所在房间必须一致 | 好友关系、在线状态、当前公开可见活动 | 在线状态**必须**；丰富游戏状态可简化 |
| 快速创建房间 | 创建后应进入房间并在大厅列表可见；权限不足时拒绝 | 群角色、房间持久数据 | **必须** |
| 邀请码加入 | 校验资格、密码、开放、容量和单设备活动 | 房间与邀请/资格校验结果 | **必须**，具体入口形式可调整 |
| 房间封面与网络拓扑动画 | 装饰能力，不影响组队闭环 | 可来自默认素材或成员数据派生 | **非必须，可延后** |
| 已连接时长 | 只能由真实加入时间计算，不能写死 | `joinedAt` 与当前时间派生 | 非必须，可保留轻量展示 |

**当前修正点**：离开后仍显示“已连接 42 分钟”和“回到房间”不合理；当前房间在大厅重复出现时，应降低卡片信息密度。

### 4.3 游戏房间：语音与成员

| 展示/交互 | 合理性与口径 | 数据来源 | 初版是否必要 |
| --- | --- | --- | --- |
| 成员头像与身份 | 显示当前活动有效成员，房主标识来自房间配置 | 活动成员、账号资料、房主 | **必须** |
| 说话/静音/连接状态 | 三种状态独立；说话来自音频活动，静音来自成员媒体状态 | 实时语音事件与连接事件 | **必须** |
| 静音/关闭接收 | 立即改变本地控制，失败时提示，不影响虚拟网络 | 本地音频组件 | **必须** |
| 输入输出设备、测试、总音量 | 展示当前真实设备与权限；测试必须有真实结果才能标成功 | 操作系统与本地音频组件 | **必须** |
| 成员独立音量 | 只修改本地接收 | 本地偏好 | **必须** |
| 邀请队友 | 选择具体好友并发送有效邀请；不能只是泛化的“邀请好友” | 好友、群籍、邀请与房间资格 | **必须** |
| 16 人容量 | 第 16 人可加入，第 17 人拒绝；保留账号占额 | 活动与保留记录 | **必须** |
| 延迟 `28 ms` | 只有真实探测后才能显示；可改成质量等级 | 语音传输探测 | **非必须，初版可隐藏** |

**当前修正点**：所有房间的房主和成员不能固定为阿岚等 6 人；邀请入口需要具体好友选择；精确延迟可删以减少伪精确数据。

### 4.4 游戏房间：文字聊天

| 展示/交互 | 合理性与口径 | 数据来源 | 初版是否必要 |
| --- | --- | --- | --- |
| 历史消息与发送 | 发送中、成功、失败与重试；历史默认长期保留 | 房间/群消息持久数据 | **必须** |
| 成员加入系统提示 | 只由真实成员活动事件生成 | 活动事件 | 可简化，但不得伪造 |
| 删除本人消息 | 删除需确认，原位置显示作者删除提示 | 消息作者、当前账号与删除结果 | **必须** |
| 管理员代删 | 仅当前群主/管理员；追加只读管理记录 | 当前角色、消息与管理记录 | **必须** |

**当前修正点**：现原型只实现发送，需补回删除、管理员代删和失败状态，避免需求覆盖倒退。

### 4.5 游戏房间：虚拟局域网联机

| 展示/交互 | 合理性与口径 | 数据来源 | 初版是否必要 |
| --- | --- | --- | --- |
| 网络连接状态 | 与语音独立；未成功不能显示“已就绪” | 虚拟网络代理和探测事件 | **必须** |
| 本人与成员虚拟 IP | 地址在活动内唯一，只有分配成功且有权查看时展示 | 当前活动网络分配结果 | **必须** |
| 复制 IP | 复制失败时显示可手动选择的值，不能假装复制成功 | 已分配地址与系统剪贴板结果 | **必须** |
| 三步手动联机说明 | 确认实际游戏主机成员 → 复制该成员地址 → 游戏直接连接；必要时补充端口说明。织界房主不等于游戏内主机 | 全部当前成员的地址、用户约定与静态帮助 | **必须** |
| 地址冲突/权限不足/失败 | 原因可区分、可重试，不能统一显示连接失败 | 虚拟网络代理错误与系统权限 | **必须** |
| 互联网/物理 LAN 边界 | 明确不代理普通互联网，不转发物理 LAN 其他设备 | 产品边界说明与后续真实路由验证 | **必须** |
| 游戏自动发现与兼容承诺 | 首版不自动发现游戏；工具互通不等于游戏跨平台 | 无 | **明确不做** |

**当前修正点**：成员页顺序生成 IP 与联机页本人 IP 存在冲突，必须改为同一网络分配数据源。

### 4.6 房间设置与活动管理

| 展示/交互 | 合理性与口径 | 数据来源 | 初版是否必要 |
| --- | --- | --- | --- |
| 编辑名称、游戏、房主 | 按当前群角色/房间权限；保存成功后列表同步更新 | 房间持久配置与执行时资格 | **必须** |
| 修改密码 | 只影响新加入，不清退现有成员 | 房间配置结果 | **必须** |
| 暂停/重新开放 | 暂停阻止所有新加入但不清退现有成员；重新开放须在房外 | 房间开放状态与当前活动资格 | **必须** |
| 结束活动 | 清退成员、终止语音与网络，保留配置和暂停状态 | 活动生命周期结果 | **必须** |
| 删除房间 | 终态，终止全部会话与恢复；需明确确认 | 房间删除与撤销结果 | **必须** |
| 切房/设备转移 | 先预检并保留旧活动，再原子切换；失败不错误双活动 | 活动代次、设备归属与目标资格 | **必须** |

**当前修正点**：原型保存、暂停和结束操作不能只弹成功提示，至少应更新模拟状态并展示影响。

### 4.7 好友页

| 展示/交互 | 合理性与口径 | 数据来源 | 初版是否必要 |
| --- | --- | --- | --- |
| 在线/全部/待处理 | 数量来自同一好友与申请数据集，不包含自己 | 好友关系、在线状态、申请 | **必须** |
| 昵称或账号 ID 搜索 | 两种字段都应真实匹配，空结果有下一步 | 好友账号资料 | **必须** |
| 添加、接受、拒绝、删除 | 操作后列表、数量和关系状态同步；重复操作幂等 | 好友关系服务端结果 | **必须** |
| 资料卡与共同群组 | 只展示当前用户有权知道的共同群组 | 账号资料与共同群籍 | 可简化，但账号 ID 必须准确 |
| 邀请入群/组队 | 好友身份不自动授予权限，接受邀请后才建立关系 | 邀请与目标资格 | **必须** |
| 好友私聊 | 不在已批准首版范围 | 无 | **明确不做** |

**当前修正点**：大厅“5 在线”包含自己；部分好友同时出现在不同房间；搜索不支持 ID；资料卡 ID 不一致；接受申请未更新数据。

### 4.8 群组与群聊

| 展示/交互 | 合理性与口径 | 数据来源 | 初版是否必要 |
| --- | --- | --- | --- |
| 我的群组列表 | 只显示当前账号已加入群组，不提供公开群搜索 | 当前群籍与群资料 | **必须** |
| 群资料、成员与房间数 | 从群数据计算，切换不同群不能共用固定人数 | 群成员、在线状态、房间列表 | **必须** |
| 长期群聊 | 历史保留，发送/删除/代删规则与消息一致 | 群消息与权限 | **必须** |
| 创建私密群组 | 创建后立即可见，只通过邀请或邀请码加入 | 群持久数据 | **必须** |
| 群邀请 | 当前成员可邀请；撤销仅限群主/管理员；失效原因明确 | 邀请、邀请人群籍、群生命周期 | **必须** |

**当前修正点**：切换不同群时，群成员数和在线数仍固定为 8/5，需改为群级数据。

### 4.9 群组管理

| 展示/交互 | 合理性与口径 | 数据来源 | 初版是否必要 |
| --- | --- | --- | --- |
| 成员与角色 | 按当前角色展示可执行操作，执行时再次校验 | 当前群籍、角色与目标成员 | **必须** |
| 群主转让 | 指定成员接受前原群主不变 | 转让请求与接受结果 | **必须** |
| 群主退出/解散 | 退出前必须转让或解散；解散后产品内不可恢复 | 群生命周期与当前角色 | **必须** |
| 人工恢复申请 | 只提交申请和证据引用，不自动继任 | 人工处理结果 | **必须**，渠道可简化 |
| 只读管理记录 | 仅当前群主/管理员；无修改、删除、清空入口 | 追加式管理记录 | **必须** |
| 移出成员 | 撤销同步、语音、网络、恢复和设备资格；不等同封禁 | 当前资格与撤销结果 | **必须** |

**当前修正点**：普通成员不应看到可点击的群主危险操作；拒绝不能只依赖前端隐藏，真实实现必须执行时校验。

### 4.10 设置、账号与支持

| 展示/交互 | 合理性与口径 | 数据来源 | 初版是否必要 |
| --- | --- | --- | --- |
| 账号验证与登录设备 | 登录设备与活动设备分开；活动状态随真实资格变化 | 账号、登录设备、活动设备租约 | **必须** |
| 设备转移 | 预检、原子替换、旧设备失效 | 活动代次与设备归属 | **必须** |
| 音频偏好 | 本地保存并在重新渲染后保持 | 本地设备与偏好存储 | **必须** |
| 安装、更新、卸载说明 | 三平台能力需要真实实现与验证 | 发布制品与平台测试 | **必须** |
| 支持矩阵 | 候选、验证通过、未验证分开，不自动承诺游戏兼容 | 发布维护的实测矩阵 | **必须，可简单表格** |
| 全局搜索 | 跨好友、群组、房间的统一搜索不是已批准核心能力 | 可由本地已加载数据派生 | **非必须，可延后或移除** |
| 通知中心 | 完整通知历史不是核心；先完成邀请与错误提示即可 | 邀请、活动、系统事件 | **非必须，可简化** |

## 5. 初版范围清单

### 5.1 初版必须完成

- 邮箱账号、验证、登录退出与找回。
- 好友搜索、申请、接受、拒绝、删除和在线状态。
- 私密群组、邀请、角色、群主治理、长期消息和只读管理记录。
- 持久房间、16 人容量、密码、开放状态、房主与活动生命周期。
- 加入、切房、设备转移、断线保留、恢复和旧会话撤销。
- 真实多人语音、静音、关闭接收、设备选择、音量与设备异常处理。
- 真实虚拟网络、唯一 IP、复制、手动游戏连接、隔离和错误处理。
- 语音与网络独立状态、独立失败和独立恢复。
- 三平台安装、更新、卸载和真实支持矩阵。

### 5.2 初版可以简化

- 房间封面使用统一默认素材，不建立游戏资料库。
- 好友状态只展示在线/离线和可公开的所在房间，不做复杂 Rich Presence。
- 通知只保留邀请与必要错误提示，不做通知中心历史。
- 网络质量只显示连接状态，精确延迟、丢包和抖动可后置。
- 拓扑图可移除或仅按成员派生，不做动画与复杂可视化。
- 支持矩阵使用维护型表格，不做自动检测和自动兼容承诺。
- 全局搜索移除，保留各页面内必要搜索与筛选。

### 5.3 首版明确不做

- 好友私聊、公开群搜索。
- 游戏自动发现、游戏数据爬取和未经验证的兼容声明。
- 普通互联网代理、物理局域网其他设备转发。
- 支付、商业化管理、独立封禁后台。
- 与核心闭环无关的装饰性首页信息流。

## 6. 当前原型优先修正清单

### P0：影响状态可信度

1. 统一 `activeRoomId + sessionStatus + voiceStatus + networkStatus`，离开后立即移除个人活动信息。
2. 加入中不显示已连接、28 ms 或可用 IP；语音与网络分别驱动界面。
3. 统一房间数据源，切换房间时同步游戏、房主、成员、聊天和容量。
4. 统一 IP 分配数据，修复本人 IP 与成员 IP 冲突。
5. 修复好友在线数量包含自己、跨房间状态冲突和账号 ID 不一致。

### P1：影响交互闭环

1. 创建/保存/暂停/结束房间后更新模拟数据，不只显示成功 Toast。
2. 好友申请、删除、搜索和邀请后更新列表与计数。
3. 补回消息删除、管理员代删、切房和设备转移走查。
4. 群组人数、在线数和房间数按当前群计算。
5. 未入房作为默认演示场景；已入房作为独立返回用户场景。

### P2：影响展示效率

1. 正文与联机步骤字号提高至 12～14 px，减少过小文字。
2. 降低大厅当前房间的重复信息密度。
3. 删除或简化无实际数据支撑的精确延迟、拓扑动画和全局搜索。
4. 装饰性封面与状态图形不得替代真实状态标签。

## 7. 推荐落地顺序

1. **统一数据与状态模型**：先保证任何页面都不会互相矛盾。
2. **补齐核心交互闭环**：加入/离开、创建/管理、好友/群组、消息与权限。
3. **按初版范围删减弱必要展示**：优先减少假数据和伪精确指标。
4. **最后调整视觉层级**：字号、密度、动效和封面。

完成以上评审后，下一轮原型修改应以 P0 和 P1 为主，不继续添加新页面。
