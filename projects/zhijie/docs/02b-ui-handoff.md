# WEAVORA UI 开发交接契约

阶段 B2_UI，任务 UI-B2-004；依据已批准需求 REQ-001～REQ-029 与 B1 基线 APR-B1-15e3bfc1a414。设计稿候选，不等于服务实现。人工确认前不进入 C/E。本文与可操作页面、组件工作台共同构成交付，不以截图替代行为定义。

## 1. 设计问题与取舍

| 原问题 | 设计决策 | 判断方法 |
| --- | --- | --- |
| 宣传式大标题占据任务入口，页面像展示海报 | 页面标题直接使用大厅、群组、好友、设置；短副标题说明当前任务 | 首屏不用阅读广告语即可定位功能 |
| 房卡只见游戏与箭头，不知道属于哪个群、与谁玩 | 自上而下排列游戏/容量、群归属、房名、玩法、开放状态、队友、加入按钮 | 不进房即可判断对象、容量和下一步 |
| 页面存在两个创建房间操作，争夺视觉权重 | 内容标题区只保留一个创建主按钮；卡片加入使用中性按钮，当前活动回房用主按钮 | 检查同一内容区域的主动作数量，不删除主导航快捷创建 |
| 当前活动区用网络概念装饰和固定说明 | 紧凑展示当前房名、人数、语音/联机各自实际模拟状态、回房动作 | 隧道失败时语音等待；音频专属故障不停止可用隧道 |
| 群卡只有统计与泛化入口 | 群标识、名称/简介为主体；成员与房间数、在线队友、活动摘要为辅助 | 原数据为唯一来源，不生成虚构活跃度或消息 |
| 联机重复三步教学挤压成员地址 | 保留实际游戏主机说明；单行“复制 IP → 游戏直接连接”；地址列表优先 | 所有地址可查看和复制；必要端口提示不删除 |
| 错误只有短暂 Toast，用户不知道改哪里 | 对可定位输入显示持续内联错误、aria-invalid、aria-describedby 与字段焦点；保留原值 | 错密码不清空、不退出旧房间；用户修改后清除旧错误 |
| 退出弹框默认焦点落在右上角 X | 确认类优先聚焦底部“取消”，表单类先聚焦首字段 | Tab/Escape 仍由原处理器管理；确认退出动作不变 |
| 组件状态只写在文档里 | 设计系统工作台能实际演示等待禁用、重试、字段校验及修正 | 非静态换色；样例明确标为模拟，不串改产品数据 |

设计假设：以固定游戏小队的重复使用为主，而非新用户品牌落地页。此为设计判断，尚无用户访谈、点击热图或可用性实验，不以断言数宣称用户满意。

## 2. 页面任务契约

| 页面/入口 | 用户问题 | 主动作 | 辅助信息与退出条件 |
| --- | --- | --- | --- |
| 大厅，未入房 | 谁在玩，加入哪里？ | 具体房卡加入；标题创建 | 群归属、游戏、人数、队友、开放状态；验证码加入为次按钮 |
| 大厅，已入房 | 现在在哪个队伍，如何返回？ | 当前活动回房 | 各通道状态及共享隧道依赖；切其他房必须走现有目标校验 |
| 房间/聊天 | 哪些队友在线、谁在说话？ | 麦克风与消息发送 | 房主/本人标识、说话/静音文字、容量；成员区独立滚动，不占用发送区 |
| 房间/联机 | 复制谁的地址？ | 对应成员复制 | 不把织界房主当游戏主机；网络未连接不能展示可用 IP |
| 群组 | 进入哪个固定小队？ | 卡片进入，标题创建 | 邀请固定在列表工具栏；有待处理才显示角标；卡片显示当前有效群数据 |
| 群聊 | 聊什么，去哪一局？ | 发送文字或进入群内房间 | 本人消息靠右，群房间与管理入口保持；不新增好友私聊 |
| 好友 | 找到并邀请某个人 | 邀请组队/添加 | 筛选与账号搜索保留；无悬停也能发现邀请 |
| 设置 | 改设备，处理账号，查支持 | 当前页签控件 | 同级页签都在页内，设备转移和退出才弹确认；不把模拟设备当实机 |

空状态只有一个与当前任务相关的下一步。大厅无房间引导群组，群组为空可查看邀请；搜索无结果保留查询，不能用假卡片填满布局。加载状态只在真实存在的连接/重试中表达，不添加无业务依据的假进度。

## 3. 组件属性与交互约束

| 组件 | 必需输入 | 状态与行为 | 不能由视图决定的事项 |
| --- | --- | --- | --- |
| RoomCard | id、game、name、desc、group、members、open、passwordRequired、isCurrent、canManage | 默认/悬停/焦点/按下；开放、暂停、满员、当前房间；管理入口弱化；最多展示三个头像，其余 +N | 容量、群籍、密码、设备及执行时授权都由可信域校验 |
| CurrentSession | 当前房间、人数、voice/network 状态 | 两通道原样派生，不使用固定成功说明；回房按钮 | 不能由页面导航创建第二个活动 |
| GroupCard | 名称、标识、简介、有效成员/房间与在线状态 | 默认/焦点/悬停；统计按群计算，不能泄露无群籍内容 | 不以好友关系获得群权限，不凭客户端统计改变角色 |
| ChannelStatus | channel、state、reason、retryAllowed | disconnected / waiting / connecting / connected / limited / retrying / failed；文字+颜色；重试中与成功有区别 | 隧道就绪后才连接语音，逐成员失败如实显示，无服务器回退 |
| FieldFeedback | 字段、错误原因、是否已编辑 | 失败保持输入，焦点回字段；错误持续到编辑或重新校验；同一错误不重复全局播报 | 不能用客户端字段校验替代服务器规则 |
| ConfirmDialog | 标题、可选影响、取消/确认动作、危险等级 | 表单优先字段，确认类优先取消；Tab 限定，Escape/X/背景只取消；确认按钮才执行 | UI 不自动批准、删除、转移或重试高影响操作 |
| ActionButton | label、importance、disabled、busy | primary / secondary / ghost / danger；default / hover / focus / pressed / disabled / busy | 真实异步 busy 必须绑定服务请求，不靠固定时长模拟成功 |
| InvitationEntry | 待处理数量、有效历史记录 | 大于零有角标及可访问数量；零不显示 0，不隐藏入口 | 接受/撤销的资格和幂等由域逻辑处理 |
| ReplicaSync | scope、当前资格、可达副本、已有内容、tombstone | 无在线副本提示暂不可用，可重试；本机合法内容仍可读；群同步无需入房 | 视图不能开放跨房游戏/语音；重连先取得当前资格及删除状态；最后副本丢失不保证恢复 |
| MessageReceipt | messageId、delivery、接收端确认、逐成员进度 | pending / transferring / received / partial / failed；文字说明与模拟标识，部分完成保留其他成员待同步 | 元数据登记、本机 Object URL、字节 100% 不等于接收端持久化；重复乱序收敛由协议处理 |
| MessageMedia | type、name、授权后的媒体引用、删除状态 | 图片按钮打开查看对话框并返回焦点；视频 controls + metadata，不自动播放；删除只保留提示 | 视图不生成公开永久链接，不以本地 Object URL 证明投递；读取、Range 和删除撤销由当前控制面授权与客户端执行，不能绕过 tombstone |
| MediaTransfer | scope、活动代次、文件、附言、status、progress、error | empty / selected / uploading / checking / sending / failed / revoked / expired / invalid；忙碌防重复、取消可达、失败保留输入并可重试 | 文件安全探测、配额预留、幂等、活动资格、迟到回调及在途撤销不能由视图决定 |

`system.html` 的 busy/重试仅用于可操作的组件规格；产品当前的内联校验连接到真实存在的本地模拟错误。未来服务接入时应替换数据源和请求适配，不将演示定时器搬进正式服务代码。

## 4. 状态与反馈时序

### 加入、切房

点击 → 打开确认/密码表单 → 校验目标 → 保留旧活动或成功切换 → 虚拟网络 connecting，语音 waiting → 隧道就绪后连接语音；失败则等待。密码错误保留弹框与原输入，内联说明，不离开旧有效活动。暂无真实服务错误，不编造“服务器忙”等状态数据。

### 连接失败与恢复

状态标签、失败原因和重试入口分别归属对应通道。未连接网络不显示可用地址；隧道失败则语音等待、对应成员内容传输不可用。音频专属失败保留可用隧道。不使用服务器回退，NAT/禁 UDP 可能直连失败。复核工具可模拟权限、设备拔出、服务断线和保留期，普通入口不展示开发工具。恢复资格和迟到结果沿用批准逻辑。

### 消息与媒体

选择文件 → 本地预览 → 待发送 → 客户端直传 → 接收端独立校验 → 接收端落盘确认。无对端时本机保存/待同步；部分完成为部分送达，不宣称全员已接收。本机保存或直传、校验和确认期间禁止重复提交及更换文件，取消保持可达；失败保留预览和附言，重试仍绑定原会话及活动代次。本机保存消息可进入列表但须标待同步；仅接收端确认完整校验落盘才标对端已接收，控制面登记不作为投递成功；取消、过期、失权或校验失败不得生成幽灵消息。图片点击查看，关闭后焦点返回原消息；视频只显式播放。当前原型用定时器模拟异步阶段，正式客户端必须按当前控制面授权校验资格、逻辑预算、格式与代次，接收端独立验证，并撤销旧读取和在途传输。

### 退出、删除与解散

退出始终确认；未入房只有标题与两按钮，有活动才补充中断说明。取消保持账号、页面、IP 与连接。删除/解散保留不可恢复说明，群解散另有名称确认。正式异步失败不提前移除对象，成功后才回列表；这一服务器时序是开发契约，未实现部分不能当作本轮验收通过。

### 表单与反馈

错误显示在字段下方，13 px、危险语义色，且与字段通过 aria-describedby 关联。全局错误保留 Toast，能归属弹框/字段的错误用内联说明代替重复播报。错误源只包含当前既有模拟校验；不对密码值、验证码或令牌添加日志。

## 5. 布局与极限

- 1440 px：84 px 主导航、302 px 好友侧栏；内容内边距 36 px，三列房卡，20 px 间隔，房卡封面 112 px、正文 18 px。群列表宽度上限 1120 px，两列群卡。
- 901–1220 px：隐藏好友侧栏、房卡两列；房间联机栏至少 340 px。不能因窗口变化将各通道状态及底层依赖合并为单一成功。
- 601–900 px：房卡两列、群卡一列、房间上下布局；玩家卡两列，最小高 150 px；玩家与消息/联机分别滚动。
- 600 px 及以下：房卡一列、玩家卡保留两列；群卡页脚可换行；底部导航与语音条分层，弹框确认按钮至少 44 px。不是原生移动端支持承诺。
- 16 人：成员卡区域滚动，不不断缩小头像和字号；不挤掉发送框、联机页签或离开入口。长昵称/群名折行；IP 等宽不省略；头像堆叠 +N 只用于摘要，完整成员仍在房间查看。
- 键盘、少动态、焦点、指定颜色对比度与错误关联有自动检查；系统字体、全部透明合成色、高对比度模式、读屏完整体验及 200% 缩放仍需专项走查。

## 6. 设计实现边界

`presentation.js` 是 UI 层适配：只重组页面呈现、语义标记、焦点与反馈。加入、角色、容量、撤销、邀请、恢复逻辑继续复用批准原型；B1 源文件不改。此适配不是生产组件架构；正式阶段按上表拆成组件和状态接口，而不是复制本文件对全局函数的替换模式。

交付包含 `index.html`、`ui.css`、`presentation.js`、`system.html`、`system.css`、`system.js`、构建/测试、离线 HTML、截图与本契约。截图只用于视觉检查，可操作页和状态样例才用于验证交互。C 阶段再确定框架、桌面容器、服务接口与可信权限边界，UI 阶段不擅自预设技术栈。

## 7. 复核标准

1. 每个页面的对象、主动作、当前状态一眼可辨，且与已批准任务一致。
2. 成功、失败、等待、禁用、取消与空状态具有可执行定义，不以颜色或静态图冒充实现。
3. 对比度和字号服务可读性，错误可修复、焦点可预测、危险动作不会误触。
4. 数据来自现有模拟对象，敏感规则由域检查；所有后续未实现服务明确标记。
5. 人工应亲自走查任务，并判断信息密度与品牌质感；自动测试是防回归，不是专业审美或用户验证的代替品。

## 8. 生产状态接口与验收边界

仅控制面（Java，含内部数据库）及 Lighthouse 在线，不引入 SFU、LiveKit、TURN、业务 Relay 或内容缓存服务。控制面只接收最小身份/授权/顺序/删除/预算元数据，内容传输、存储及音频由客户端完成；控制流量仍存在。

视图消费隧道及逐成员可达事件、音频连接事件、实际字节进度、独立校验结果、持久化 ACK、当前授权/到期、tombstone 及磁盘状态。重试使用原消息 ID 和当前资格，丢收据不得生成重复消息。waiting 不得标为失败或成功；received 仅至少一个对端完整落盘确认，partial 明示其他成员待同步。

群附件 10 GiB 是逻辑引用预算，本机磁盘满拒收不删历史。未提交草稿 15 分钟过期；取消立即不可读；临时对象累计运行 24 小时清理，停机跨墙钟期限则启动先清理。受控路径目标 5 秒撤销，失联授权到期停止，不承诺抹除已下载副本。UI 不能以定时器代替这些真实条件。

当前 B1 模拟副本模式和三种收据，UI 复用该逻辑，不新增协议。完整逐消息传输中/失败、磁盘满、缺失内容占位、群头像同步、真实 NAT 矩阵、重连删除顺序及离线授权到期仍需后续实现。AC-044～AC-048 真实验收均未验证，界面断言不等于产品交付证明。
