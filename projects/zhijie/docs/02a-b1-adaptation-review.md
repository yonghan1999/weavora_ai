## 结构与交接

原型的 `domain.js` 负责模拟资格、状态变化和故障注入，`app.js` 负责界面；二者是设计工具，不是已批准的生产实现。配额使用单常量，群消息使用单数据源，减少显示、发送和权限分歧；未新增媒体后端、生产依赖或无用扩展。

架构阶段优先评估 Rust 承担客户端核心、音频接入、网络辅助及 IPC；不因此锁定桌面容器，也不默认重写服务端。建议交接契约如下，字段及协议由 C 阶段定案：

| 边界 | 命令/状态要求 |
| --- | --- |
| 界面 → 客户端核心 | 加入/退出/切换、通道重试、设备选择、静音/降噪、开始/停止设备测试、群文字发送/删除；均携带当前目标标识 |
| 核心 → 界面 | 当前活动/版本、通道状态与可信原因、设备权限/处理可用性、测试状态、群消息及目标群；连接成功后才开放可用地址 |
| 运营控制 → 网络核心 | 策略和版本由可信配置提供；普通用户/群管理员无配置权限；禁用不能自行回退，强制中继不能自行直连 |
| Rust/特权辅助进程 | 网络权限及平台设备操作不从页面直接执行；IPC 校验身份、目标、版本和权限；秘密不送入普通日志 |
| 测试隔离 | 复核工具与模拟计时器不进入正式产品；不得把浏览器变量当成可信授权或路径证明 |

保留资产：`styles.css`、SVG图标、游戏封面样式、房卡、头像和语音条。适配资产：`app.js`、`domain.js`、交互测试、截图与单文件导出。B2 的 `presentation.js` 仍含旧容量显示及旧布局覆盖；当前 UI 入口不是本轮审查入口，必须在新 B1 批准后独立适配并回归。
