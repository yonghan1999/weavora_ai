# 工具适配与真实能力说明

## 当前适配器：交互式 Coding Agent + 本地 CLI

当前环境可读写文件、执行命令和测试、保存状态与审计、暂停等待人工操作。入口为根目录 `zhijie.py`，仅依赖 Python 标准库。Kimi Work、其他 Coding Agent 或人工终端均可调用相同 CLI。

AI 的职责：读取契约、澄清需求、填写文档、配置任务与检查、执行非审批命令、分析失败并修复。人类审批者独自执行 `approve`。当前适配器没有独立后台 Agent 守护进程，不会在新需求到达后自行唤醒；需要用户在交互会话中重新调用 AI 或由人工运行命令。

## 未接入能力

- 未接入外部模型 API 或多 Agent 调度服务。
- 未实现 Web 界面、消息队列、远程执行集群或生产部署。
- 本地 CLI 通过显式确认值和具体审批人记录区分人工命令，但不提供操作系统身份认证或数字签名；共享终端环境仍须用权限和流程保护审批命令。
- 未来业务项目的构建工具按需选择；初始化不安装业务依赖。

## 添加其他适配器

适配器只需：读取状态与文档、传递标准任务输入、调用非审批 CLI、读取结构化结果。审批应接到真实人类身份或等效确认渠道。不得通过自动写 `approved`、伪造证据或直接修改状态来绕过执行器。

## 命令安全

`task-run` 和 `verify` 会在项目工作区执行显式登记的本地命令。开发任务的执行命令必须与任务契约中的 `test` 完全一致；F/G/H 分别要求 `self_tester`、`test_engineer`、`test_engineer` 角色。执行超时限制为 1–3600 秒，超时会终止进程树；输出通过临时文件收集，每项证据最多保留 1,000,000 字节并记录截断。

这些约束不是操作系统安全沙箱，命令仍可继承当前用户权限并访问工作区之外的资源。只运行已审查、必要且最小权限的命令；涉及外部副作用、生产数据或不可逆操作时先取得人类授权。不可信输入不得直接转为命令，共享主机须通过独立操作系统账户、文件权限或真正沙箱隔离。秘密通过安全的运行时机制提供，不写入文档、状态或证据。

## 持久化与本地信任边界

项目写入使用跨进程操作系统文件锁，进程退出后锁自动释放；单个 JSON 文件通过同目录临时文件原子替换。框架元数据修改由项目级回滚日志保护：异常或进程崩溃后，下一次带锁访问会先恢复状态、审计、任务、检查和审批文件；新项目创建中断也可安全重试。外部命令副作用以及未纳入日志的业务工作区文件不由该机制回滚。证据 SHA-256 和审批文件交叉校验用于发现误改和不一致；能够同时修改全部本地文件的攻击者仍可重算摘要，因此它们不替代真实身份认证、签名或只读审计存储。
