# Agent 输入输出契约

机器可读 Schema 位于 `workflow/schemas/`。适配器可在任何 Coding Agent 与本地命令入口之间转换，但不得省略证据或审批字段。

## 任务输入

每个角色开始任务前必须获得：工作流标识、任务标识、当前阶段、目标、已批准需求和设计基线、相关文件、约束与禁止事项、验收标准、可用工具与权限。无基线的阶段应明确写“尚未形成”，不能编造。

## 任务输出

每次执行结束应形成结构化结果：

- `result_status`：`completed_verified`、`completed_unverified`、`partial`、`failed`、`waiting_human`。
- 实际创建或修改的文件。
- 关键决策及依据。
- 实际执行命令、退出结果和证据路径。
- 未完成事项、风险与阻塞原因。
- 建议下一步与推荐状态迁移。

推荐迁移仍须由执行器校验；Agent 无权直接改写状态或审批 JSON。

## 证据要求

1. 文件必须实际存在且位于项目目录。
2. 命令证据必须含时间、退出码、输出和执行角色。
3. 构建或测试不可运行时，状态只能是 `completed_unverified`、`partial` 或 `blocked`，并记录原因。
4. 测试后代码变化使 F/G/H 旧证据失效。
5. 完成依赖未完成、缺少验收标准或追踪断裂时，门禁失败。

## 角色交接

交接最小单元是“任务契约 + 文件路径 + 证据路径 + 当前状态”，不是整段对话。新会话可通过 `status`、文档和审计日志恢复上下文。
