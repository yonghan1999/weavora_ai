# Agent 输入输出契约

机器可读 Schema 位于 `workflow/schemas/`。适配器可在任何 Coding Agent 与本地命令入口之间转换，但不得省略证据或审批字段。

## 任务输入

每个角色开始任务前必须获得：工作流标识、任务标识、当前阶段、目标、已批准需求和设计基线、相关文件、约束与禁止事项、验收标准、可用工具与权限。无基线的阶段应明确写“尚未形成”，不能编造。

B1 产品原型必须基于已批准需求；B2 UI 必须基于已批准需求和原型；架构、开发及测试交接必须包含已批准的原型与 UI 路径。原型文件是设计基线，不代表后端、性能、安全或设备兼容性已经实现或验证。

## 任务输出

每次执行结束应形成结构化结果：

- `result_status`：`completed_verified`、`completed_unverified`、`partial`、`failed`、`waiting_human`。
- 实际创建或修改的文件。
- 关键决策及依据。
- 实际执行命令、退出结果和证据路径。
- 未完成事项、风险与阻塞原因。
- 建议下一步与推荐状态迁移。

推荐迁移仍须由执行器校验；Agent 无权直接改写状态或审批 JSON。

## 证据要求

1. 证据文件必须位于项目 `tests/evidence/` 目录，证据标识、项目标识和文件名必须一致。
2. 命令证据必须含时间、退出码、输出、截断标志、执行角色、命令和代码树哈希。
3. 最近证据的 SHA-256 保存在对应任务、检查或用例记录中；文件被修改或摘要缺失时门禁失败，须重新执行。
4. 证据命令必须与登记命令一致，任务/检查/用例上下文必须匹配；G/H 用例证据还必须来自对应阶段。
5. 构建或测试不可运行时，状态只能是 `completed_unverified`、`partial` 或 `blocked`，并记录原因。
6. 测试后代码变化使 F/G/H 旧证据失效。
7. 完成依赖未完成、缺少验收标准或追踪断裂时，门禁失败。

## 角色交接

交接最小单元是“任务契约 + 文件路径 + 证据路径 + 当前状态”，不是整段对话。新会话可通过 `status`、文档和审计日志恢复上下文。
